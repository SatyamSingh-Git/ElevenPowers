# 67 — A wrapper is not another check

The staged sessions preserved both projects' checked behavior, but their tests
did not link to native declared-command evidence. The agents ran a directory
prefix before the exact check. Completion later made milestone receipts current;
that did not repair the missing observation of the agent's own execution.

Removing every prefix would be easy and wrong. A changed directory can run a
different project; a pipeline or trailing `echo` can hide failure. The repair
therefore recognizes one literal `cd` into the same project root, followed by
the exact declared command. Dynamic paths and unsupported shell setup remain
unqualified. Tool-directory metadata is checked on the shared ingress path,
including direct Claude callbacks.

Identity also has to survive storage. The receipt keeps the actual invocation
and the declared check separately. History and fresh-result reuse now select
the latter; otherwise a wrapped failure would leave an older direct success
looking current. Missing status and directory attribution stay incomplete, and
changing the declaration still makes the prior observation stale.

Twenty-four actual Python/npm commands through Windows cmd and Git Bash supplied
forward and adversarial controls. A wrong-directory check really passed and was
still rejected as incomplete. A failure masked by `|| echo` supplied no declared
binding. Replay callbacks wrote no native activation state. This repairs and
measures the capture seam; it is not a new installed-session or coding-improvement
result. Those exits remain open.
