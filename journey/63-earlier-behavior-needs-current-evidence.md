# 63 — Earlier behavior needs current evidence

The user asked what should come after ImpactGraph and approved building the
next milestone. The concern had shifted from a single isolated patch to a
system developed over several tasks: a later change should not make an earlier
feature disappear from verification just because the conversation moved on.
The standing requirement remained project independence.

The first delivery uses an optional tracked declaration of behavior expectations,
inputs and exact commands. It reuses existing receipts and freshness rather than
introducing a second verdict engine. A bounded archive lives in the same locked
atomic ledger save and survives task transitions. It never becomes current task
claim evidence. Reports distinguish current, failed, stale, incomplete and absent
checks while preserving execution, result and freshness as separate observations.

Inspection runs no project checks and writes no project state. An explicit CLI
can add explained ImpactGraph leads, and the existing portable report includes
the section for opted-in projects. Missing graph paths cannot certify unaffected
behavior. Declarations do not launch commands; existing host capture retains
matching receipts automatically once the project opts in.

The independent exercise builds provider, checkout and worker stages, keeping
earlier receipts while adding components. After a provider expiry-boundary edit,
the view becomes stale before any fresh execution. Actual checkout and worker
assertions reject the fault, and the view then records failed checks. Repair and
an equivalent implementation pass. An unrelated Node layout independently rejects
its fault and accepts repair. All 18 producer attempts are preserved: 15 qualified
passes and three assertion-fault rejections. The check files remain unchanged.

The useful adverse result is the scope control. Native whole-source receipts
also expire after an unrelated source addition. A separate controller producer
observing the full explicit declared scope stays current after that addition.
This demonstrates the existing scope distinction; it does not make native
attribution selective by declaration. That cost stays visible in the guide and
the remaining roadmap work.

The implementation also exercises strict malformed declarations, unsafe paths,
history limits, command/scope mismatches, later incomplete attempts, old writers,
empty tests, input edits with unchanged mtime, deletion, report movement and
read purity. Two additional impact controls exposed an unbounded direct-lead
branch and an argument validation shortcut on unconfigured projects; both were
seen failing before correction. Architecture render caught an oversized label
and verified the shortened version across all five views.

The fresh whole-branch review then found equal-timestamp stale replay and a
declaration error that never recovered. New controls reproduced both. Saved
observation identities now distinguish a new append from replay, and transient
declaration errors are read from the current file. Unknown historical gaps
require new matching observations for all current checks before they clear.
Deleting the declaration stops capture. These corrections preserve conservative
qualification while allowing ordinary repair to recover.

This is a delivered capability with independently specified fault/control
checks. It is not a measured coding gain or installed-session acceptance result.
The next exit is qualification of precise attribution and ordinary usage cost,
followed by a matched end-to-end comparison measuring preserved behavior,
missed regressions and total work. Automatic milestone blockers remain outside
this first release; PatchProof remains separately scoped for contribution.
