# 82 — a workflow needs a native trial

The declared-check runner closed a concrete shell-boundary gap: an owned failed
child could stay failed even when the surrounding command succeeded. Actual
Python/Node controls demonstrated the mechanism. They did not demonstrate that
an installed agent would discover and use it while developing a project.

The next milestone connects those questions without merging their conclusions.
The installed pilot now has three tasks and checks a native runner call, a fresh
owned receipt and task-specific callback provenance. A controller-run command
or a final answer is insufficient. The independent consumer must remain current
while the affected one becomes stale, fails and recovers.

The outcome comparison uses two authored four-stage systems: a durable Python
queue and a Node order/reservation system. Their requirements interact through
expiry, stale identities, exact accounting, persistence, batching and replay.
Independent oracles revisit earlier contracts after every stage. Valid references
and known behavior-breaking variants exercise both directions before any model
conversation can be treated as a coding comparison.

One control caught an assumption in the measurement itself. Moving an expiry
boundary broke both leasing and restart behavior. Counting only the first named
group would have hidden a second real loss. Another distinction matters just as
much: a feature that never passed is an earlier failure, not a newly introduced
regression. Missing grades remain unknown.

Delivery failures stay in view. If configured feedback fails to arrive but the
pair's source outputs can still be independently compared, that outcome remains
in the comparison. Discarding it would make the tool look better by removing
its failed deliveries. A live timeout or unidentified conversation remains a
scheduled incomplete attempt rather than a silent omission.

The first two native conversations completed all six turns. Both code fixes
passed independent arithmetic checks, but neither workflow qualified. Build
evidence was missing after the first task. Python's failed dependency remained
stale instead of receiving a failed receipt; JavaScript did record the failure.
Both recovery prompts inherited the preceding task identity.

One failure belonged to our measurement interface. The synthetic diagnostics
in the initial test supplied prompt/tool task fields that the real producer
left empty. Python had used the owned runner, so its false native-adoption flag
could not honestly mean no adoption occurred. The old result stays retained;
the producer needs the task association rather than a relaxed qualification rule.

Real callback controls reproduced six failures. Shared repairs now recognize
explicit new-task declarations without inventing claims, correlate native
prompt/tool callbacks and expose independent declared-property commands within
a bounded context. Seventy affected controls pass, including ordinary
continuations and unbound callbacks. They apply to every project and host.

The larger comparison stopped at the readiness gate. Repaired source qualified
with 2,519 local tests, three skips and all four hosted cells. All 107 audits,
the independent grader, eight historical source grades and eleven doctor checks
pass. A new installed allowance is needed before proceeding. [The validation
record](../docs/validation/2026-10-16-installed-multistage.md) retains the original
attempts and exact producer identities. Earlier correctness ties remain unchanged;
these controls do not establish a coding-quality advantage.

All qualified source reached main at `366048d`. The five rendered views were
deployed and their HTML/data bytes independently matched the committed files.
The final record adds documentation only. Native requalification remains a
separate, allowance-gated next step, with both original failures retained.
