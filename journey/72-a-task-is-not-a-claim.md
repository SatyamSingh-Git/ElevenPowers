# 72 — A task is not a claim

The installed exercise started with an ordinary request: read the instructions
and follow them. Claim inference correctly avoided inventing a promise to fix a
bug. Task correlation incorrectly depended on finding such a promise, so the
session never acquired the identity needed to join its observations.

The runtime now opens an identity for every nonempty initial prompt. A clearly
new subject starts an isolated task; a continuation retains the original request,
claims and evidence. A second witnessed defect mattered here: preserving only
the ID was insufficient, because replacing a question with `continue` changed
how the next edit was classified. Both the identity and subject now survive.

A separate parser defect mistook pytest warning-filter values such as
`ignore::UserWarning` for node IDs. Known option values are now separated from
positional targets, while actual file/node and expression selection stays scoped.
Unknown plugin option arity is reported as unqualified instead of guessed. Real
pytest subprocesses supplement the command-text regression controls.

The latest Windows reference check also failed once and passed on rerun. A
controlled delayed constructor reproduced a queue-grader setup defect: threads
spent a shared barrier deadline while other threads were still constructing
queues. Setup now finishes before concurrent claims begin, keeping the expected
claims and deadlines intact. The original failed scenario was absent from the
log, so the reproduced defect is not presented as its proven cause.

The rehearsal producer now opens tasks through ordinary prompt callbacks across
all five hosts, without controller-seeding identity. Replay, synthetic ingress
and installed sessions remain separate categories. These changes remove observed
integration failures; they do not turn prior correctness ties into a product
benefit. See [validation](../docs/validation/2026-10-11-ordinary-session-evidence.md)
and [observations](../results/ordinary-session-evidence/README.md).

The user approved two fresh subscription sessions, specifying Sonnet 5.5 at medium.
Both the Python and JavaScript installed exercises passed all twelve checks with
the original read prompt, in 206.184 seconds total. Native advice emission and
current follow-up receipts were observed in both. This is useful integration
progress: the first claim-less installed attempt's missing identity is repaired
without making up a claim. It is still two cells of ten, and a prescribed check
following advice cannot establish that advice caused better coding.

The complete local suite finished at 1,985 passing tests and two skips. Hosted
Linux/Windows 3.11/3.13 qualification passed all four jobs, but only after one
Linux cleanup regression failed and then passed unchanged on a failed-job rerun.
That failure is retained; its cause remains unknown. Successful repeated CI is
not a diagnosis. The closing docs record this limit and preserve the exact green
runtime revision instead of claiming a newer test run for documentation prose.
