# A comparison needs a working host

2026-10-02. Fresh project health was built, but its central delivery question
remained: does an installed coding agent actually send the events that make the
plugin useful? The next milestone joined versioned native acceptance, measured
read costs and a subscription coding comparison. Every runtime path is general;
the large external repository is an acceptance case, with no special policy.

The user clarified the outcome criterion. A task can be small or large. An
observable improvement in coding or verification through any engaged mechanism
counts: a gate, stale evidence, scope, planning, blast radius or flow. Task size
cannot substitute for that result, and neither can a passing installation probe.

Native evidence now binds new preparation and real startup to a bounded content
identity of shipped software. Explicit contained probes observe installed
versions. Captures omit paths, prompts and output; a ten-cell matrix leaves
missing, conflicting, old and incomplete evidence visible. Repeated health reads
retain every attempt, source coverage and timing. Three-read samples measured
139.088 ms median for a small unrelated project and 2,511.143 ms for the large
external repository. These are dated read costs, not a speedup or ordinary-session
callback overhead. The actual producer exposed an incorrect assumption that a
project fingerprint had the same length as the software identity; the positive
project sample failed before that validation was corrected.

The comparison froze an original multi-module atomic/idempotent batch problem,
visible contracts, behavioral checks and prompt before model outcomes. Two
replicates of baseline and plugin arms ran on each of two hosts, with equal
240-second allowances and medium effort. Requested models were exactly
`gpt-6.1-sol` and `claude-sonnet-5-5`, through verified subscription authentication.
API-key and provider overrides were refused. The plugin never launches this
comparison automatically.

The pilot did not establish a coding improvement. All four Codex candidates
remained unchanged; native command attempts were rejected by policy. All four
Claude calls failed, with later diagnosis observing the weekly subscription
limit. No native callback arrived in either tool arm. Eight journalled records
make the run history complete; they do not make the comparison valid. All original
records remain published, including their original evaluator identity. A later
archive reader reproduces those saved aggregates without models or silent
regrading and labels them as an earlier evaluator.

Running the installed producers corrected launch assumptions. Codex's supported
automatic approval review conflicts with an explicit sandbox flag. Claude needs
project and local settings to load the owned local hooks. A separate Codex
exercise reviewed its five hooks and accepted normal native trust through the
host UI. The agent then changed the boundary source and observed the declared
test fail before and pass after. Still no callback was received or processed.
That exercise omitted the incomplete/stale steps and remains waiting. Trust in
the host UI is not evidence that the runtime received its events. The dated
compatibility matrix is still 0/10.

Independent review exposed five Important evaluator/export failures. Candidate
code could impersonate final grading output; legitimate package imports failed;
an unsupported resolved record counted as success; failure metadata could leak
private strings into archived exports; JSON erased tuple/list distinctions.
Each reproduction was observed failing before correction and passing afterward.
The controller now owns final assertions, the contained worker preserves normal
imports and bounded tagged behavior, and all archived states receive metadata
and grade validation. Changing worker/grader bytes creates a new protocol;
the original eight-run results are not rewritten. This separation is not an OS
closed-book boundary.

Two Minor findings remain: deleting sealed metadata is reported as setup rather
than invalidation, and the sixteen behavioral checks do not cover invalid account
identifiers already present as balance keys. Neither can support a stronger
correctness claim. Expanded behavioral coverage belongs to a new protocol.

The user increased publication to 29 meaningful parts with descriptive commit
messages. Runtime work was pushed as its focused controls passed, followed by
review corrections, architecture and documentation. Broad checks run at the
delivery boundary. The next priority is native callback delivery and a newly
identified, quota-available comparison that can observe the plugin contributing
to coding. Preserve neutral and worse outcomes as well as improvements.
