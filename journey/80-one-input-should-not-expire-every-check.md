# 80 — One input should not expire every check

The previous milestone made dependency drift visible. It also treated every
declared dependency as an input to every command. Two independent checks could
therefore lose their evidence together when only one dependency changed.

This milestone adds an explicit project assertion: an exact declared command
can name a complete set of witness IDs. Partial or absent declarations keep the
broad contract. Historical receipts never acquire a narrower history from a
new declaration. The collector still reads the configured union under aggregate
budgets; the new scope qualifies results rather than claiming to discover every
dependency automatically.

Actual Python and JavaScript consumers made the distinction observable. Each
had a separate dependency and a launch counter. The first independent fault
failed when executed directly. In the scoped comparison the second command kept
its execution evidence through the fault and repair; in the broad control it
ran again. Both preserved the relevant failure. An unchanged nested PatchProof
bundle read each selected file twice, instead of the eight reads reproduced
before sharing operation-local opening and closing observations.

Those initial observations were made before final review. Their runtime and
limits remain recorded in [the preliminary result](../results/command-input-scopes/README.md).
They are command and read-count controls, not a coding-quality or latency result.

The review found three real gaps. A literal redaction replacement could collide
with a secret-bearing command's public identity. A broad external admission
discarded an independent saved execution, and early invalidation then invented a
source-change diagnostic. A late external guard cleared the main association
but left a dedicated external field saying bound.

All eight Python/JavaScript regression cases failed before repair. The repaired
group passed 30 checks. Ambiguous raw or already redacted identities now refuse
narrowing. Saved execution is admitted per command, with source guards kept
separate; an unavailable unused witness remains visible without blocking the
sole required independent command. Late opaque failures clear the public
external associations consistently.

Installed acceptance uses two tasks in each same persistent conversation,
sharing one three-minute allowance per language. Host callbacks must establish
the task transition. Controller-created tasks cannot substitute for that
observation. Model-free continuation and independently checked arithmetic remain
separate measurements.

Both approved conversations completed two host-created tasks in about a minute
each. Both fixes passed the arithmetic oracle, and the independent milestone
stayed current through the affected dependency's drift. But the models appended
an `echo` trailer to the failing command. The exact identity did not match, so
the second task did not retain a new declared failure receipt. This is partial
installed acceptance. Treating the shell chain as an exact command would hide
the distinction the evidence is meant to preserve. No extra sessions were run.

The first full hosted suite then found what the focused groups had missed: a
receipt Markdown import shadowed the bundle formatter. It returned a list where
the bundle needed a string, and was unbound when no receipt used it. Linux
reported 23 failures, including several older race probes whose injection
interfaces or expected capture counts had changed. The four CLI formatter tests
passed after the alias correction. The race probes were moved to actual current
boundaries and made to assert that their adversarial mutation fired. The first
qualification was stopped; its artifact success did not make the suite green.
Installed observations retain their earlier recorded runtime identity.
