# A rule a person certifies

Twenty of the 31 v3 losses were one rule kept in two files, with the agent
changing one. Every detector tried so far points at the other file some of the
time and at the wrong file far more often. As a standing warning, shared rare
tokens fire on most stages that need nothing. This entry is about where that
noise should be paid for.

**Three detectors first, each planned before it ran.**

- **Co-readers** ranked files by the rare inputs they read in common with the
  edit. It found 5 of 17 held-out dependents, with a control of 0, but fell
  under its in-sample bar. It misses when the edited helper reads nothing
  itself and its callers hold the input.
- **Same state** came from a paper's anchor: requirements interact through the
  state they constrain. It ranked by the fields the edit writes, and found 0
  of 17. A held-out contract is an assumption about data, such as "rows arrive
  sorted", not a shared field name. A first note claiming contracts were
  positional formats was written before reading their paths, and was wrong.
- **Data flow** followed calls to the touched functions, and found 4 of 51.
  The data travels through files and objects, not calls.

**A fresh set, so no result rested on what had been read.** Every detector so
far had been shaped or judged on the 17 stages behind the losses. The other
51 declared dependents had never been opened. Ranked from each case's own
reference, with the dependent left behind, they gave the shared-token ranking
its first clean test: 16 of 51 in the top 3, against a control of 6.

**The design came from somewhere else.** NVIDIA Auto-Ontology is a database
tool, with no code to borrow, but it has a loop:

1. a machine discovers a map;
2. a person certifies it once;
3. agents are grounded only in what was certified.

The noise that ruins a warning on every edit costs one review when a person
reads it once. ElevenPowers already had the certified half: milestones list
input files. Proposals made from the project alone, before any change, cover
20 of the 51 fresh dependents at 50 per project (control 11, random 3.9).
One review at the start does as well as reviewing before every stage.

**Built:**

- `ep_milestones --propose` lists the pairs, with their shared words as the
  reason and an entry to certify. It writes nothing.
- Only declared rules reach the agent. They appear in the brief before it
  first edits one of the files, and in an end-report line when a declared
  rule changed in only some of its files.

Replayed on a real loss, both named the report the agent had left behind.
Attacking the finished work found one defect: two proposals could share an
id, and the schema refuses that. Whether an agent acts on the brief is the
open question it hands on.
