# 50 — A configured hook is not an active integration

2026-10-01. The user approved onboarding and live diagnostics, then reinforced
the constraint: every feature must work across projects. Snag is an acceptance
repository. Its name, location and npm commands are absent from runtime rules.

The five adapters already shared scanning, receipts and completion verification.
The first-use gap was that setup could write a correct configuration while doctor
could only say a live session was unverified. Native patch events also could not
tell whether an already-dirty or non-Git file changed.

The delivery extends the existing merger and project lock. Claude joins the four
native additions in project setup. Automatic host selection refuses ambiguity.
Readiness combines wiring, callback activation, discovered commands, runtime
availability, source selection, latest execution and next actions. It does not
run tests or infer source freshness from a stored passing result.

Activation records launcher ingress separately from fixture/replay execution.
They retain counters, timestamps, events and exception classes without raw
prompts, outputs, session IDs or exception text. Received callbacks are a
diagnostic observation, not authentication of a host.

Patch target headers come from the documented apply_patch input envelope and
grammar exercised by the actual patch tool during implementation. File content
is compared across pre/post calls, bound to task, session, call and input. The
mechanism works with non-Git files and preexisting edits, additions, deletions
and moves. It says nothing about unrelated side effects or which concurrent
writer produced the observed bytes.

One fresh review reproduced four defects: a matcher that never delivers but
doctor accepted, missing session scope that allowed cache collisions, missing
post-events that silently lost edit coverage, and quoted interpreter paths
reported missing. Each was watched failing before correction. The missing-event
fix also exposed pending state in status, reconciled completion, and preserved
uncertainty when bounded pending history evicts a baseline. Different execution
directories and bounded host identities received additional controls.

The generalized checks include unrelated Node, Python, Cargo and Go projects,
parallel launcher counters and cross-project activation isolation. The initial
broad run passed 1,055 tests with 28 skips while corrections were landing; a final
run was required against the settled code. Exact final results are in the
[validation record](../docs/validation/2026-10-01-live-onboarding.md).

Snag setup preserved its existing local permissions. An installed Claude Code
2.1.281 startup delivered and processed SessionStart with no prompt/model call.
Codex remained configured and waiting; replay did not turn that into activation.
The actual external npm CI failed: 14 of 15 checks passed, with five unexcused
high-or-critical dependency findings in the production audit. The real result
was relayed explicitly into a complete/fail receipt. No business source or branch
was changed, no audit was bypassed, and no paid evaluation was run.

Installed command capture remains separate from this relay, and live sessions on
the four added hosts remain open. The next delivery is a portable verification
report: make the receipts, source freshness and unknowns reviewable by someone
who did not watch the session. That is the report-as-product direction in PLAN,
applied to ordinary project use rather than another gate.
