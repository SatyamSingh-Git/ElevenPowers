# 55 — At the moment of done

The user asked for benefit through any mechanism, on any task size. The next
question was therefore what changed when the plugin actually acted. Final code
alone could not answer that: a gate may have seen a bad proposal and repaired
it, or it may have added expense after a proposal was already correct.

Claude's ordinary native startup worked after trust in our owned fixture. A
quota-available coding session then delivered 31 callbacks. Command capture
still looked absent: the agent ran tests with a directory prefix and an echo
suffix. Accepting the wrapper's status would weaken the exact-command contract.
The exercise now asks for standalone command calls on every host and project.
A second session captured fail/pass and fresh completion. Interrupted execution
is still unqualified, so full platform acceptance remains open.

We borrowed the old checkpoint idea but stopped staging the candidate. A frozen
file allowlist now records each proposed completion before and after the plugin
action. Both arms get the observer. One real producer check found another
mistake: NTFS updated access time when a file was read, and comparing the whole
stat result treated that as an edit. The regression was watched failing before
the correction. Reading a candidate now changes neither source nor Git index.

Eight subscription runs used Sonnet 5.5 medium: an atomic repair and a correct
refactor control, two arms, two repeats. Every first proposal and final candidate
passed the independent 16 checks. No gate blocked and no code repair followed a
block. This pilot cannot be sold as better patches.

Three treatment proposals lacked an exact-command receipt, and ordinary
completion supplied a fresh one. Final evidence coverage was 4/4 treatment and
1/4 baseline. This is a real change in retained evidence. It does not prove
baseline skipped tests: wrappers remain a measurement gap. The initial summary
called any refresh benefit; publication keeps that original file and explicitly
separates receipt improvement from coding improvement.

The public archive can reconstruct every proposed/final synthetic candidate;
24 independent grades matched without another model call. The next useful
comparison needs ordinary defective or stale first proposals on held-out work.
We now have the instrument to see them and retain what happens, including
another neutral result.

The fresh review found four gaps in future comparisons, even though the saved
eight runs were valid: a later recording failure could leave an earlier history
looking complete, project settings and prepared files could drift, the evaluator
entry point was not fingerprinted, and preflight could fail before leaving an
attempt. Each was reproduced before correction. New batches freeze inputs at
preparation and retain attempts before authentication and every Stop. Independent
capture markers and native treatment counts must agree with the history.
Reproduction also preserves an old evaluator identity when checkout line endings
change its bytes. See [dated evidence](../docs/validation/2026-10-02-proof-of-benefit.md).
