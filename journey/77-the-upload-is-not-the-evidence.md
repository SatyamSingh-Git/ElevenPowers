# 77 — The upload is not the evidence

The next delivery was supposed to make PatchProof useful to another person:
show its exact patch, existing receipts and missing checks in GitHub, then let
the reviewer download the underlying bundle. Before adding that surface, the
latest main CI repeat exposed a Windows cancellation failure that an earlier
qualification had passed.

The process returned exit 1 while its original kernel handle still said it had
not terminated. In a local twenty-attempt probe that happened nineteen times.
Python's cached return code let `wait()` return early after asynchronous
termination. The repair waits on the original Windows handle inside the same
remaining cleanup deadline. The survival assertion stayed intact. Thirty
expanded repetition rounds passed in each of four hosted cells. Older unrelated
cleanup, launcher and SQLite incidents remain unexplained.

The presentation reuses the existing bundle rather than inventing another
verdict. Declared PR base/head must match the selected commits. The summary
names failed, stale, absent and incomplete evidence, full patch identities and
coverage gaps. Large tables can be shortened, but their omissions cannot
disappear. A prototype fallback dropped those notes; a second control exposed
coverage counts disappearing too. Both failed before repair.

Actual checks in three separate disposable projects produced passing, failing
and interrupted results. Each executed once. Reading and exporting did not
execute them again. The real hosted Action then wrote its summary, uploaded
the two public files and returned a download URL. Downloading the artifact and
recomputing its canonical bundle hash established which bytes arrived. It did
not establish that the patch was safe.

One independent review found three problems that ordinary happy-path transport
had missed. Known credential-shaped dictionary keys escaped value-only
redaction. An external path hard-linked to project source defeated the path
guard. A cold vendored runtime created bytecode despite an environment setting
ignored by isolated Python. All three were reproduced; the repair also refuses
redacted-key collisions and checks an opened runner descriptor before writing.
Private configuration keys are preserved.

This adds a review surface to the evidence we already collect. It does not add
an LLM judgement, a safety percentage, an authenticated attestation or a causal
coding-benefit result. Live PR/fork publication and richer external-input
witnesses remain separate work. The exact checks and publication observations
are in the [dated record](../docs/validation/2026-10-13-github-evidence.md);
the reusable interface is in the [guide](../the-guide/patchproof-github.md).
