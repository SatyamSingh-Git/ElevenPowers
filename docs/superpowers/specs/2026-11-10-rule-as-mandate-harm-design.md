# Does "change both" do harm where only one side should change?

*Written 2026-11-10, before any run. It follows
[the confirmed instruction wording](2026-11-09-rule-as-mandate-confirmation-design.md)
([result](../../../results/rule-mandate-confirm/README.md): 5 of 60 lost
against 23 of 60).*

## Why

`ep_milestones --propose` now writes every rule as "`A` (file) and `B`
(file) must stay consistent: change both in the same task". That default was
checked for harm on one stage only, where one such rule (`annual.py`) was
never acted on wrongly.

On **45 of the 95** v3 stages other than that one, the correct reference
changes one side of a reviewed rule and not the other
([rehearsal](../../../results/rule-gate/rehearsal.json)). There, "change
both" is the wrong instruction. If agents obey it, they make needless edits.
If those edits break behaviour, the new default does harm.

## Arms

Both arms: superpowers plus ElevenPowers, the `guide` profile, and the blind
reviewer's kept rules for every case (`results/rule-gate/accepted.json`).

| arm | description of every rule |
|---|---|
| `rules` | the old template: "These files keep the same rule (they share …)" |
| `described` | the new default: "`A` (file) and `B` (file) must stay consistent: change both in the same task." |

The described texts are generated by `results/rule-mandate/describe.py` for
all 12 cases, in
[`descriptions.json`](../../../results/rule-mandate-harm/descriptions.json).
`household_budget` is byte-identical to the confirmed run, and the longest is
174 characters.

## Runs

- Every one of the 45 stages, 1 run per arm: 90 runs.
- Sonnet 5.5 at medium effort, under the standing authorization.
- About $15 and 35 minutes. Each slot runs once and none is retried.
- **Power:** one run per arm across 45 strata. The harm batch's calculation
  ([power](../../../results/rule-groups-harm/power.txt)) gave 79–88% to
  detect a harm of 20 points, but that was over 53 strata. Over 45 it is
  somewhat lower, and smaller harms can be missed.

## Outcomes, fixed now

**Primary (harm).** Any group lost, `described` against `rules`. Exact
one-sided stratified test over the 45 stages that `described` loses more,
α = 0.05.

**Secondary, reported whatever they show:**
1. **Needless edits.** The agent changed a file that a rule left behind by
   the reference names, where the reference does not change that file.
   Counted per arm.
2. **Dependent lost**, where the stage has a declared quiet dependent.
3. Cost and wall time per arm.

## Decision rule, fixed now

- **`described` loses more at α = 0.05:** the proposer's default reverts to
  a description, and the README qualifies the benefit as applying only where
  a person means "change both".
- **No measurable harm, but clearly more needless edits** (at least twice as
  many, and at least 5 more in total): the default stays. The guide warns that
  the instruction should be kept for files that must really change together,
  and the needless edits are reported.
- **Neither:** the default stays, and the harm-free claim extends to these
  45 stages.

## Gates before any money

1. `prepare` refuses descriptions that do not name exactly each case's
   certified rules, so the sealed protocol is the check that every
   description reached its rule.
2. **One-slot harness check,** read in full.

## Bounds, known now

- **One run per arm per stage,** so a stage-level difference is noise. Only
  the pooled test is read.
- The v3 cases are built, not real projects.
- **Needless edits** are counted by file, not by whether the edit changed
  behaviour.
