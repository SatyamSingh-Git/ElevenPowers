## Existing boundary and implementation choices

Actual native responses emit both property instructions, but Windows renders
each as an opaque encoded invocation with identical labels. New no-edit tasks
receive no prompt guidance because they infer no coding claim. Native ordinary
compound commands leave stale/absent evidence. Their echoed exits must never be
reinterpreted as owned execution. The cause of agent non-adoption is not yet
established; these repairs address observable guidance defects, not a guaranteed
causal explanation for every failed trial.

Reuse core.checks, core.jobs.Session, native transport, invocation quoting,
ledger/source/external-input qualification and the existing installed pilot.
No dependency, shell parser, project-specific command or new completion blocker.
The author chooses two connected deliverables:

1. Readable property labels, honest completion wording and bounded owned-check
   advice on explicit new verification tasks, including tasks without edits.
2. An explicit all-declared-check batch command with one owner/deadline and
   independent receipts/outcomes. This is the additional requested feature.

## Guidance contract

Keep core.checks.guidance(root, commands=None) returning executable per-property
instructions, tests first, at most 2,000 characters, with named omissions.
Labels identify the property outside encoded shell text. Quoting remains
host-shell-neutral. Add optional batch=True to present one --all invocation plus
the exact declared property list. A command filter always retains selected
per-property instructions rather than broadening to all checks.

Startup/resume guidance prefers the batch after it is implemented. Completion
wording explains that automatic obligation checks do not establish every declared
property; verification tasks should use the owned entry point. New task prompts
with explicit verify/verification/recheck/rerun/validate intent receive the same
bounded instructions through the existing transport. No claim is invented, no
command is run, and continuation/duplicate prompts or unrelated read requests
do not receive repeated advice. Off remains silent and executes nothing.

## Batch contract

`ep_check.py --all --project PATH --seconds 120 [--json]` executes every supported
effective declaration once in deterministic tests/build/typecheck/lint/benchmark
order. Property, --list and --all are mutually exclusive. --list stays read-only.
No arbitrary command text or dependency installation is accepted.

`core.check_batch.execute(root, *, seconds=120)` returns schema_version 2,
selected property names, per-property existing schema-1 results, aggregate state,
issues and elapsed time. Same finite positive <=600-second total limit as the
single runner, including scans; existing bounded process cleanup is separate.
One Session owns the entire batch. Existing single-check execute remains
compatible and shares an internal owner-aware implementation, never nested locks.
Each property's exact source/config/producer/task/external checks and provisional
receipt remain independent. Failed checks do not suppress later independent
checks. Deadline exhaustion, task/config/producer movement and interruption
leave explicit incomplete/unrun outcomes and durable journal state. No result
is reused as a pass; no absent child result is invented. Empty declarations,
off, invalid budgets and busy ownership launch nothing.

Aggregate passed means every selected check passed; incomplete takes precedence
if any selected check is incomplete/unrun; otherwise a failure yields failed.
Human output retains `Declared check PROPERTY: STATE` lines so existing native
observers can join per-property owned receipts. JSON contains metadata, no captured
outputs, prompts or exception bodies. CLI exits 0 passed, 1 failed, 2 incomplete,
130 interrupted. This is trusted project command execution, not a sandbox.
