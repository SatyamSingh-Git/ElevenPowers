# Declared workflow checks and overhead implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline, with one fresh whole-result review. Steps use checkboxes.

**Goal:** Diagnose and repair the observed declared-check qualification gap and avoidable runtime overhead using generalized, no-model controls before installed qualification.

**Architecture:** Reuse existing command qualification, owned execution, native hooks, milestone guidance and bounded scan/report primitives. Preserve earlier comparison records; add no language/project special case or weaker command attribution. Choose the smallest repair after retained trace and component measurements identify its boundary.

**Tech stack:** Existing Python standard-library runtime, pinned pytest development environment, real Python/Node commands, existing native launchers and browser map checker.

**Spec:** [Bounded workflow repair](../../design/workflow-checks.md), the user-authorized follow-up to [matched findings](../../../results/matched-workflow/README.md) and the existing [declared-check contract](../../design/declared-check-execution.md).

## Global constraints

- Generalized for any project and all host adapters; authored fixtures only in tests/evaluation.
- No-model checks first. Preserve task versus exact milestone states and genuine failure/incomplete outcomes.
- Existing frozen comparison/oracle/source originals remain immutable; no favorable retry or historical regrading as a new producer.
- No new dependency, shell evaluator, broader automatic execution, completion blocker or enabled optional engine.
- Performance findings distinguish native/runtime work from inference, service variation and application performance.
- Reuse the clean authorized main checkout and push verified meaningful parts frequently.
- Standing Sonnet 5.5 medium subscription authorization applies only if needed after fresh no-model/source qualification; no API fallback and retain every attempt.

## Review focus

- Compound commands and masked exits must never acquire owned or exact-command evidence from text alone.
- Missing configuration, off/quiet policies, continuation tasks and interrupted checks preserve existing behavior.
- Shortcuts must not bypass source/configuration/runtime/input movement or depend on persistent stale caches.
- Bounded advice and native callback transport remain optional; emission does not prove consumption.
- Measure actual subprocess/scan work and unrelated Python/JavaScript controls before claiming a runtime cost reduction.
