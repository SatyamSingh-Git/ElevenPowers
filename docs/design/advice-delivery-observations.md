# Observable milestone advice delivery

The next milestone follows the repaired native command qualifier. Contributors
and users need to distinguish a worker returning text, a launcher emitting that
text through its host context contract, and a later native check matching a
recommendation. None of these observations proves model comprehension, causal
usefulness or improved coding outcomes.

Build on ElevenPowers' existing Apache-2.0 bounded advice reservations, native
callback correlation, transport adapters and fresh evidence export. Add a
last-mile emission observation and a read-only temporal join; do not introduce
another evidence engine, raw transcript archive or acknowledgement instruction.

## Design and alternatives

Worker-only logging is cheap but cannot detect dropped context. Asking an agent
to echo a marker would add ceremony and still provide only an agent assertion.
Instead, the launcher observes successfully flushed output, checks that the
actual supported context field contains its prepared advice, and retains bounded
metadata. Recommendation identities come from the same portable report that
renders advice. Later fresh receipts are joined through existing native links.

The feature extends existing flows and changes additive diagnostic fields only.
Execute inline under the user's request to build and push, preserving the clean
checkout on a dedicated branch. No additional process approval round is needed.

## Contract

- Preserve `automatic.deliver(ledger) -> str` and legacy `status=delivered` as
  worker-context availability. Label this meaning explicitly in new views.
- Workers return at most six recommendation hashes, for the six visible checks,
  each derived from exact portable `[kind, command]`; retain no command bodies,
  prompts, context bodies, outputs or raw task/session identifiers in advice state.
- A launcher-scoped collector holds prepared text in memory only. After stdout
  is successfully written and flushed, observe supported `additionalContext`
  or `additional_context` fields, including `hookSpecificOutput` envelopes.
  Exact prepared context must survive the transport. Other response fields and
  substring mentions of advice do not qualify.
- Native callback correlation supplies host, configuration generation, task and
  session hashes. Emission records include runtime/content hashes and timestamp.
  Replays, direct library calls, dropped context, failed writes, old generations,
  absent sessions and disabled/off projects cannot create qualified emissions.
  Recording failure never creates evidence or changes a completion decision.
- Extend the existing atomic, ignored advice state (20 tasks, ten attempts each,
  64 KiB). Keep reservations/deduplication/cooldown/task budgets unchanged. Legacy
  rows remain readable but cannot retrospectively prove emission.
- Readiness adds `milestone_advice` separately from required pipeline stages.
  Distinguish disabled/unconfigured, waiting, generated, emitted and incomplete.
  Join only current task/startup session/generation/runtime, intact wiring, and
  exact recommendation identities with later matching native receipt keys.
  A later receipt may be current, failed, stale or incomplete; earlier/controller
  receipts cannot establish a native follow-up. Absence stays unobserved.
- Retain all fallback checks and coverage qualifications. Diagnostics never
  certify that advice was read or caused an action, and never change verification
  receipts, task verdicts, optional activation or automatic command execution.
- Model-free controls use disposable unrelated Python and JavaScript projects,
  real local commands, and explicitly replayed hook callbacks. Native-ingress
  launcher controls are documented synthetic invocations, not installed sessions.
  No old experiment archive is changed or retroactively qualified.
