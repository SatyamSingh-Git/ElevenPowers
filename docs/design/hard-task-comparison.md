# A harder controlled comparison

Approved in chat on 2026-10-02: four authored, held-out scenarios, one baseline
and one ElevenPowers run each, eight calls maximum at 480 seconds per call.
The subsequent model instruction selects subscription Claude Sonnet 5 at medium
for both arms. No paid API fallback, model substitution, extra favorable rerun,
or hidden-check feedback is allowed. Preparation and grader validation are free.

The previous Sonnet 5.5 medium comparison remains unchanged. Every first proposal
passed its 16 checks, a ceiling that could not reveal a correctness improvement.
This new comparison increases interacting behavior rather than merely the number
of assertions: durable competing leases, async lifecycle races, incremental graph
invalidation, and transactional byte-stream recovery. These are synthetic tasks,
not evidence about a population of real repository issues.

Reuse the existing native proposal observer, subscription authentication,
contained runner and sealed prepared-input protocol. Extend the evaluation flow
with an explicitly selected frozen suite. Preserve default behavior and the
original archive reader. There is no project-specific runtime policy or automatic
evaluation during plugin installation.

Both arms receive identical issue text, initial source, conventions, visible
checks, allowed files, model, effort, tools and wall-clock allowance. Alternate
arm order across tasks. Treatment uses ordinary guide behavior; optional mutation
engines stay disabled. Both arms may improve a named regression-test file; existing
tests and configuration are frozen. Hidden scenario assertions stay outside the
candidate and never supply completion feedback.

Grade initial, each before/after native completion proposal, and final source in
disposable directories. Before model execution show that each correct reference
passes, buggy initial code fails, and multiple plausible faulty implementations
are rejected. Concurrency uses actual SQLite transactions and deterministic
async event schedules, with bounded watchdogs; failure and timeout remain visible.

Report every run, independent check groups and failures, proposal-to-final changes,
actual interventions, fresh exact-command receipts, elapsed time, and incomplete
execution. A tool-arm advantage is a paired outcome observation. A causal repair
requires an observed intervention followed by a correctness improvement. Neither
receipt refresh nor additional callbacks establishes better code. Eight calls
cannot establish a population effect, throughput gain or statistical significance.

Freeze task, evaluator, runtime, configuration and prepared-source identities
before execution. Persist setup attempts, quota errors, incomplete runs and
neutral/worse outcomes. Retain snapshots for independent regrading without models.
