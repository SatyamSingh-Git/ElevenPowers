# Preserve behavior while adding the next feature

Approved direction, 2026-10-08: qualify installed editing advice, its cost and
whether it helps preserve behavior across development stages. Runtime behavior
remains project independent. No default activation or new completion gate is
introduced by this evaluation.

## Design and alternatives

Extend the existing subscription launcher, project wiring, milestone reports
and contained process runner. A one-shot coding exercise cannot observe behavior
across tasks; a new workflow engine would change the intervention being tested.
Instead, use a reusable staged comparison controller with immutable starting
files, public requirements, two sequential feature requests and a separate
controller-owned grader. Each arm retains its own workspace between requests.
The native host session is resumed for the second request, within one total
eight-minute model allowance per arm. Both arms receive the same requirements
and public tests, and can add tests. Grader output is withheld between stages.

The frozen first corpus contains two authored Python systems: a leased work
queue and an inventory reservation service. Both begin with independently checked
working core behavior. Stage one adds expiry/retry semantics; stage two adds
JSON round-trip persistence without weakening earlier behavior. Independent
checks cover old behavior and new requirements at each checkpoint. These are
selected local contracts, not representative real-world issues or proof of
large-system benefit. Correct ordinary outcomes count as ties, not failed
experiments to replace.

## Intervention and attribution

Ordinary projects have no ElevenPowers hooks. Assisted projects use the shipping
Claude hooks, guide profile, project-owned milestone declarations and explicit
optional edit advice. Both arms see the same milestone declaration and public
test command. Guide-mode completion feedback, advice, scan cost and receipt
handling are the combined intervention; this cannot isolate the effect of the
graph alone. Strength analysis remains disabled. No evaluator injects a defect
or manually feeds hidden outcomes to either agent.

Capture each stage's native response, model usage, wall time, source manifest,
sealed configuration check, independent grading, current milestone view and
native diagnostics. Readiness callbacks and advice reservations are separate
from correctness. Reports retain incomplete source/graph coverage. Missing
startup/edit/command/completion callbacks cannot qualify native acceptance;
startup alone and replay never qualify it. Captures are unsigned observations,
not host authentication. Native tools are not an OS exposure boundary: hidden
grader locations are outside the candidate and prompts prohibit reading them,
but the host can technically access the filesystem. Disclose that limitation.

## Execution and qualification

The user approved four subscription sessions, Claude Sonnet 5 at medium effort,
at most 480 seconds per session (32 minutes total), without API fallback. Each
session contains two resumed requests sharing that allowance; a stage receives
at most its equal remaining share. A fresh session UUID and private slot are
created once. Authentication, version/help probes and free rehearsals precede
calls. Never retry a launched stage, resume a partial slot or replace a difficult
case. Preserve timeout, output-limit, quota, setup and scope failures.

The controller accepts explicit cases and source snapshots; fixture knowledge
does not enter core. Case paths are normalized ordinary relative files, within
bounded file/byte limits. Configuration, existing public tests, milestone
declarations and instructions are sealed. New tests are allowed; changes to
sealed files are scope violations. Independent grading copies only allowed
candidate source and the grader into a fresh private directory, with isolated
Python execution, finite time/output bounds and structured per-check outcomes.
Incomplete execution and test setup failures cannot count as regression detection.

Report each pair's independent passed checks, retained earlier behavior,
session time, captured evidence and advice activity. A correctness advantage is
a bounded paired observation, not a causal estimate. A stale-to-current receipt
refresh is a verification benefit, not improved code. Claim a linked correction
only with an archived failing proposal, a corresponding intervention and a later
independently passing proposal; final-stage snapshots alone cannot establish it.

## Acceptance

- Free gold/reverting-fault/equivalent controls qualify independent checks.
- Missing/altered inputs, changed settings and interrupted attempts stay visible.
- Genuine installed edits, captured commands and Stop events are inspected
  separately from test outcomes and replay.
- Every approved slot is archived, including failures, with no favorable retries.
- Publication includes raw bounded records, source identities, native limitations,
  equal allowances, all ties and cost. Positive claims stay within what was observed.

Built on: ElevenPowers' Apache-2.0 subscription, process, host diagnostics and
milestone implementations, plus Python's standard library. The added component
is a source-sealed staged comparison and independent preservation grading.
