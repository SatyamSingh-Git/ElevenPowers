# Ordinary installed-session evidence

The 2026-10-11 installed exercise qualified Claude/Python, but exposed missing
task identities for claim-less opening prompts. The same status review found
pytest warning-filter values mistaken for scoped nodes and a Windows 3.11
reference-grader failure. The user authorized repairing these and completing
the next milestone, with generalized behavior and frequent pushes.

## Boundaries

- Reuse the existing hook, ledger, parser and native exercise. No new subsystem,
  dependency, completion blocker, repository-specific rule or model fallback.
- A nonempty first prompt opens a task identity even without a claim. A clearly
  new subject opens an isolated task; continuations retain identity and evidence.
  Prompt classification still determines claims, never task existence alone.
- Questions/read requests must not invent coding obligations. Existing edit
  inference remains conservative; task identity only enables diagnostic joins.
- Parse pytest's positional targets separately from known option values. Broad
  runs with `-W`, config paths and option values containing `::` must
  not become node-scoped. Real file/node targets and selection options must retain their scope.
  Keep raw/configured command strings and receipt identity contracts unchanged.
- Diagnose the gold-control failure with actual producer observations and
  bounded controls. Do not relax expected behavior, retry an incorrect candidate
  into success, alter old grades or describe an unknown CI cause as established.
- Installed acceptance and advice emission remain distinct from comprehension
  and benefit. New model sessions require a specific subscription allowance;
  preparation, synthetic controls and ordinary validation make no model calls.
- Use default system temporary fixtures outside all repository Git ancestors.
  Preserve previous public archives and this milestone's private observations.

## Approach and exits

Prefer small corrections at existing ownership boundaries over a new task
classifier, importing pytest into the runtime, or widening benchmark timeouts
without diagnosis. Python stdlib supplies task IDs and tokenization; actual
installed pytest supplies the option grammar and runner output for controls.

Required exits: witnessed regressions for task creation/isolation and option
scope; unchanged continuation/no-claim behavior; informative reference failures
and a qualified Windows control; five-host synthetic compatibility; fresh
optional Python/JavaScript installed exercises after source freeze and an
explicit allowance; review, full compatibility, published docs/map and verified
main. A refused/unanswered allowance leaves installed acceptance explicitly
pending, rather than fabricated from replay.
