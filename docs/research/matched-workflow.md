# Matched multi-stage workflow provenance

This is an execution of the existing four-stage protocol, not a new task suite
or shipping runtime change. The repository declares Apache-2.0. It reuses
`eval/preservation.py`, `eval/workflow_cases.py`, the Python/JavaScript reference
fixtures, `eval/workflow_oracles.py`, `eval/workflow_results.py`, the subscription
launcher, native transcript reader and existing evidence export. No third-party
runtime dependency, new agent engine or project-specific runtime rule is added.

The [preparation record](../../results/matched-workflow/prepared.json) freezes the
qualified runtime and harness, requests, initial files, baseline grades, oracle
identities, order and time policy before any live outcome. Preparation and the
fresh sixteen-snapshot reference rehearsal make zero model calls. The two
[installed successes](../../results/check-adoption/qualification.json) establish
the prerequisite at this producer; four earlier native failures stay retained
at their original producers. The live comparison has its own denominator.

## Intervention and independent outcomes

Both arms get identical public contracts, initial production code and existing
tests, permitted new-test paths, Sonnet 5.5 medium, subscription authentication
and time policy. The ordinary arm has the integration off; the assisted arm
has the shipped guide workflow and optional bounded advice. Mutation engines
are disabled. Python runs ordinary then assisted; JavaScript runs assisted then
ordinary. This counterbalances arm order across two cases; it does not remove
service-load, cache, sampling or other temporal variation.

Each arm is one persistent conversation across four resumed requests, sharing
720 model-process seconds. The first turn reserves 180 seconds; later turns
share the remaining allowance, carrying unused time forward. Process cleanup
has a separate bounded allowance. Controller/grading wall time is recorded
separately. There is no API fallback, favorable retry, case replacement, hidden
grade feedback or human candidate repair between requests.

Independent checks run on fresh private copies of the permitted production
files, outside the candidate project. They check observable behavior against
literal outcomes and named contract groups. Valid references and deliberate
contract faults exercise the grader before live use. Agent-written tests and
completion claims do not define the independent grade. The cumulative group
counts are 4/6/8/10, including two established base groups: ten distinct final
groups per case, not 28 distinct behaviors per arm. They do not cover every
possible requirement or input.

A newly regressed group passed at the previous graded stage and fails now.
Currently failed earlier-required groups and new-feature failures are separate
metrics. Unknown prior grading yields an unknown regression count. All scheduled
arms and stages remain visible after timeout, scope, identity or grading failure.
Missing assisted delivery cannot filter a valid but unfavorable coding result.
Native adoption additionally requires completed owned calls, fresh associated
receipts and native callback/task qualification; command text alone is weaker
evidence. Ordinary arms are not expected to emit plugin callbacks.

## Reproduction and limits

The [source archive](../../results/matched-workflow/source-archive/manifest.json)
retains every scheduled slot's available production snapshots, source-file
hashes, public-case and oracle identities and independent export-time regrades.
The existing reproducer executes those sources again without a model. Historical
harness matching is separate from source grading. Evidence exports preserve
receipt qualifications, and dirty final code has no committed PatchProof subject.
Export success does not confer patch binding.

Raw native streams, prompts and diagnostics stay private; public records retain
bounded counts, hashed conversation/task identities and source/grade provenance.
These are unsigned local observations, not authenticated attestation. The native
tool policy is not an OS isolation boundary or a proof of closed-book execution.

Two authored systems, one conversation per arm and a single model/effort setting
cannot establish a population effect or identify a particular component's causal
contribution. Model-process wall time includes the native workflow and is not a
production-code performance benchmark, model-only inference time or API-dollar
estimate. Receipt completeness, runner adoption and independent coding benefit
must be reported separately. See [retained findings](../../results/matched-workflow/README.md),
[execution plan](../superpowers/plans/2026-10-17-matched-workflow-comparison.md)
and [usage](../../the-guide/installed-multistage.md).
