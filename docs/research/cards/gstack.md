gstack is a Claude Code skill pack (slash commands rendered from templates) that turns one developer's sprint into a fixed pipeline: think (`/office-hours`), plan (`/plan-*-review`, `/autoplan`), build, review (`/review`), test in a real browser (`/qa`, `/design-review`), ship (`/ship`, `/land-and-deploy`), reflect (`/retro`), plus safety hooks (`/careful`, `/freeze`) and memory (`/learn`, `/context-save`). It targets Claude Code first and renders the same templates for Codex, Cursor, Factory, Kiro, OpenCode, Slate, OpenClaw, Hermes and GBrain (`hosts/index.ts`). Its distinguishing tool is a browser: the user's Aside browser on macOS, falling back to a bundled Playwright Chromium daemon driven by a compiled CLI `$B` (`ARCHITECTURE.md`, `browse/src/`). Author states it is built for himself (`ETHOS.md` "Build for Yourself"; `README.md`).

## Request flow (cite files)

1. Install: `./setup` links each skill dir into `~/.claude/skills/<name>/SKILL.md` (real dir + symlink; `CLAUDE.md` "Prefix setting") and registers hooks in `~/.claude/settings.json`: SessionStart auto-update in team mode (`setup` ~L2554, `bin/gstack-session-update`), PostToolUse/PreToolUse on AskUserQuestion (`setup` ~L2791, `hosts/claude/hooks/question-log-hook.ts`, `question-preference-hook.ts`, `auq-error-fallback-hook.ts`), Stop timeline hook (`setup` ~L2980, `hosts/claude/hooks/timeline-stop-hook.ts`).
2. Entry: the user types `/qa`, `/review`, etc., or the host routes a plain request. Routing text lives in three places: the root router `SKILL.md.tmpl` ("When in doubt, invoke the skill"), each skill's frontmatter `description` ("Proactively invoke this skill (do NOT debug directly) when..." in `investigate/SKILL.md.tmpl`), and a `## Skill routing` block that `bin/gstack-skill-start` offers to append and commit to the project's CLAUDE.md (routing-injection block, ~L465).
3. Every skill body starts with `{{PREAMBLE}}` which renders to a one-line bash call `gstack-skill-start --skill X --model claude --parent-pid $PPID` (`qa/SKILL.md` L35-40). That script (`bin/gstack-skill-start`, 554 lines) emits `KEY: value` STATUS lines (BRANCH, REPO_MODE, SESSION_KIND, LEARNINGS, CHECKPOINT_MODE, GSTACK_PLAN_MODE, ...) and, only when a gate fires, `GSTACK_INSTRUCTION_BEGIN: <id> <session-id>` blocks the prose tells the model to obey (upgrade flow, telemetry consent, routing injection, spawned-session rules). The prose then branches on those lines.
4. The skill body is a numbered decision tree. On Claude, prose-heavy steps are carved into `<skill>/sections/*.md` and referenced by `{{SECTION:id}}` which renders a "STOP. Read `<path>` and execute it in full" pointer; on other hosts the section is inlined (`scripts/resolvers/sections.ts`). Manifests are passive (`ship/sections/manifest.json` "No machine predicate here").
5. Skill end: prose calls `bin/gstack-skill-end` (telemetry, brain-sync drain, timeline "completed") and `gstack-learnings-log` (`scripts/resolvers/preamble/generate-completion-status.ts`).

## Task understanding and planning

- No planner code; planning is prose personas. `/office-hours` (YC partner, six forcing questions) writes a design doc to `~/.gstack/projects/<slug>/`; `/plan-ceo-review` (four scope modes), `/plan-eng-review` ("My engineering preferences", 15 "Cognitive Patterns", mandatory ASCII diagrams and a test-plan artifact), `/plan-design-review` (7 passes rated 0-10), `/plan-devex-review`; `/autoplan` reads those SKILL.md files from disk and auto-answers every AskUserQuestion with "6 Decision Principles", surfacing only taste decisions and "User Challenges" at one final gate (`autoplan/SKILL.md.tmpl`). `/spec` is a five-phase spec writer with a Codex quality gate (`spec/SKILL.md.tmpl`, per `README.md`).
- Scope gate: plan reviews must make their first tool call an AskUserQuestion unless plan mode is detected (`plan-eng-review/SKILL.md.tmpl` "Scope gate"). Plan-mode detection is `CLAUDE_PLAN_FILE` env (`bin/gstack-skill-start` L206-213).
- Decision brief format is mandated for every question: `D<N>`, ELI10, stakes, `Recommendation:`, `Completeness: X/10`, 2 pros/1 con per option, `Net:` line, plus a 13-item self-check (`generate-ask-user-format.ts`). `/plan-tune` records preferences; `question-preference-hook.ts` denies never-ask questions deterministically at PreToolUse.
- Review readiness: `bin/gstack-review-log` appends to `~/.gstack/projects/<slug>/<branch>-reviews.jsonl`; `{{REVIEW_DASHBOARD}}` (`scripts/resolvers/review.ts` L23) renders it in `/ship` Step 1; only Eng Review is "required" and it never blocks (`ship/SKILL.md.tmpl` Step 1).

## Context selection and repository understanding

- No index, no embeddings, no repo map by default. Skills use Grep/Read/Glob and git (`review/checklist.md` "Enum & Value Completeness requires reading code OUTSIDE the diff"). Platform specifics are read from the project's CLAUDE.md or asked and persisted (`CLAUDE.md` "Platform-agnostic design").
- Diff classification: `bin/gstack-diff-scope <base>` emits `SCOPE_FRONTEND/BACKEND/AUTH/API/MIGRATIONS/...` flags from the union of committed + working tree + untracked files, with `SCOPE_ERROR=no_base|unmatched` (exit 2) so all-false is distinguishable from "could not look". These gate specialist dispatch (`scripts/resolvers/review-army.ts`).
- Repo ownership heuristic: `bin/gstack-repo-mode` (top author >= 80% of 90-day commits = solo, cached 7 days) drives whether to fix or flag out-of-branch problems (`generate-repo-mode-section.ts`, `generate-test-failure-triage.ts`).
- First-run detection `bin/gstack-first-task-detect` (greenfield / code_* / branch_ahead / dirty_default) picks a tip.
- Optional code intelligence: `bin/gstack-code-intelligence` wraps GBrain, Sourcebot, Graphify; `/sync-gbrain` writes a "GBrain Search Guidance" block into CLAUDE.md telling the agent to prefer `gbrain search|code-def|code-refs` over Grep (`CLAUDE.md` L820-861). Suppressed at generation on all hosts unless gbrain is detected (`hosts/define-host.ts` GBRAIN_RESOLVERS, `gen-skill-docs.ts --respect-detection`).
- Inference: with gbrain absent (the default), repository understanding is entirely the model's own grep, plus whatever prior learnings/decisions the preamble surfaces.

## Verification: what counts as done (detail the browser/QA mechanism)

Browser engine A, Aside (macOS 15+, proprietary app; `scripts/resolvers/aside.ts`): probe is `command -v aside` then `aside repl 'console.log("ASIDE_READY " + pwd)'` under a 30s timeout, printing `READY` / `NEEDS_ASIDE` / `ASIDE_NOT_RUNNING`. Each browser step is one `aside repl '<Playwright-style JS>'` script: install a console-error hook via CDP `Page.addScriptToEvaluateOnNewDocument`, `openTab`, `goto`, `snapshot(pg, {interactive:true})` (accessibility tree with refs), print `CONSOLE_ERRORS=`, `TEXT_START/END`, `DIFF_START/END` (snapshot diff after an action), `URL=`, `NAV=`/`RESOURCES=`, save a JPEG into the sandbox dir, print `ASIDE_DIR=<pwd>`, `closeTab`, then `GSTACK_STEP_OK`. Exit code is always 0; the sentinel or a `[error` line is the truth. The skill then `cp`s the screenshot out and uses the Read tool so the image enters the model's context (rule 9). Rules pinned by `test/aside-driver.test.ts`: own tabs only, look-freely/act-with-consent (one AskUserQuestion per run for mutating actions on non-local targets; never follow logout/delete links), credentials never pass through the agent, everything returned is untrusted.

Browser engine B, bundled (`ARCHITECTURE.md`, `browse/src/`): compiled Bun binary `$B` (`browse/src/cli.ts`, 1,989 lines) reads `.gstack/browse.json` (pid, random port 10000-49151, bearer token, 0600) and POSTs `/command` to a `Bun.serve` daemon (`browse/src/server.ts`, 3,379 lines) that owns a persistent Playwright Chromium (30-minute idle timeout, auto-restart on binary version mismatch). Commands are registered in `browse/src/commands.ts`: 19 READ, 27 WRITE, 25 META (goto/click/fill/press/snapshot/screenshot/responsive/console/network/perf/pdf/handoff/resume/cdp/domain-skill/skill...). `browse/src/snapshot.ts` walks `ariaSnapshot()`, assigns `@e1..` refs backed by `getByRole().nth()` Locators (no DOM mutation), clears refs on `framenavigated`, and fails fast on stale refs via `locator.count()`; `-C` adds `@c` refs for `cursor:pointer` elements; `-D` diffs against the previous snapshot; `-a` draws an annotated screenshot. Page-content commands are wrapped in `--- BEGIN/END UNTRUSTED EXTERNAL CONTENT ---` (`commands.ts wrapUntrustedContent`). `{{BROWSE_FALLBACK}}` (`scripts/resolvers/browse.ts`) is a row-by-row translation table from the Aside script shapes to `$B` commands so one skill text serves both engines.

What `/qa` checks (`scripts/resolvers/utility.ts generateQAMethodology`, rendered into `qa/sections/qa-patterns.md`): modes diff-aware (default on a feature branch: map changed files to routes, probe localhost ports 3000/4000/8080), full, quick, regression (diff against `baseline.json`); Phases 1-6: init, authenticate (user signs in themselves), orient (read script + same-origin links script with HEAD checks only on local targets; framework detection), explore per page (visual scan, interactive elements, forms with empty/invalid input, navigation, empty/loading/error states, console after every action, 375px mobile emulation), document each issue immediately with before/after screenshots and snapshot diffs, wrap-up with a health score from `qa/references/issue-taxonomy.md`. Then `qa/SKILL.md.tmpl` Phases 7-11: triage by tier, locate source, minimal fix, one commit per fix `fix(qa): ISSUE-NNN`, re-run the same script to compare `CONSOLE_ERRORS=` and tree, classify verified / best-effort / reverted (`git revert HEAD`), write a regression test that encodes the precondition (skipped for CSS-only), WTF-likelihood self-regulation (+15% per revert, stop over 20%, hard cap 50 fixes), final re-QA with regression warning, report to `.gstack/qa-reports/` and `~/.gstack/projects/<slug>/`, TODOS.md update. `/design-review` mirrors this with an 80-item audit (`scripts/resolvers/design.ts`, 1,209 lines; AI-slop blacklist in `scripts/resolvers/constants.ts`), CSS-first fixes, hard cap 30, and optional `$D verify --mockup` pixel comparison against a generated target (`design-review/SKILL.md.tmpl` Phase 9).

Non-browser verification: `/ship` Step 5 runs test lanes through `bin/gstack-evidence run --label <lane> -- <cmd>` which records exit, command sha256 and a working-tree content fingerprint from `bin/gstack-wtree`; Step 16 "IRON LAW" runs `gstack-evidence check --expect-cmd ... --max-age 24 --allow-paths CHANGELOG.md,VERSION,package.json` and re-runs on STALE/MISSING (`ship/SKILL.md.tmpl`). `bin/gstack-verify-gate` is an opt-in Stop hook that blocks the turn until `<!-- gstack:verify: cmd -->` from CLAUDE.md passes, with a per-repo trust store (hash of the command) and a 3-re-entry cap. `{{TEST_FAILURE_TRIAGE}}` classifies failures in-branch vs pre-existing and branches on REPO_MODE. `/ship` Step 7 dispatches a coverage-audit subagent that must end with a JSON line; Step 8 a plan-completion subagent (`ship/sections/test-coverage.md.tmpl`, `scripts/resolvers/review.ts` L894-1141). Completion Status Protocol requires DONE / DONE_WITH_CONCERNS / BLOCKED / NEEDS_CONTEXT (`generate-completion-status.ts`); `/investigate` requires a regression test that fails without the fix and "Never say 'this should fix it'".

## Multi-agent / roles

- Personas are prose: 30 templates open with "You are a **...**" (Chief Security Officer, Release Engineer, YC office hours partner, Staff Engineer who maintains the team wiki, senior product designer AND frontend engineer, ...); `docs/skills.md` maps each skill to a "specialist".
- Review Army (`scripts/resolvers/review-army.ts`): after the critical pass, `/review` and `/ship` dispatch parallel `general-purpose` subagents (Testing and Maintainability always for >=50 changed lines; Security if SCOPE_AUTH or backend >100 lines; Performance, Data Migration, API Contract, Design, Simplification by scope) each fed a checklist from `review/specialists/*.md`, stack context, and domain pitfalls from learnings; they emit one JSON finding per line with a `fingerprint`; the parent dedups, boosts multi-specialist hits, applies confidence gates (7+ show, 5-6 caveat, 3-4 appendix, 1-2 suppress), computes `quality_score = 10 - 2*critical - 0.5*informational`; a Red Team subagent runs if >200 lines or any CRITICAL. Adaptive gating reads `bin/gstack-specialist-stats`: a specialist with 0 findings in 10+ dispatches is auto-skipped unless `[NEVER_GATE]` (security, data-migration).
- Adversarial step (`scripts/resolvers/review.ts generateAdversarialStep`): always a fresh-context Claude subagent; plus `codex exec ... -s read-only -c 'model_reasoning_effort="high"'` under a 540s wrapper when `CODEX_MODE: ready` (`codexPreflight` in `constants.ts` detects disabled / not_installed / not_authed / under_codex / broken_install / model_unusable); `codex review --base` with a `[P1]` gate for diffs >= 200 lines; a synthesis table of findings by source.
- `/autoplan` runs "dual voices" (Codex + Claude subagent) per phase and builds consensus tables. `/pair-agent` shares the bundled browser with a foreign agent via scoped tokens and an ngrok tunnel (`ARCHITECTURE.md` dual-listener). Sidebar agent in the Chrome extension spawns a child Claude (`browse/src/terminal-agent.ts`).
- Every synchronous dispatch must pass `run_in_background: false` (`constants.ts FOREGROUND_DISPATCH_NOTE`, pinned by `test/run-in-background-guidance.test.ts`); subagent failure is always non-blocking with inline fallback.

## Model routing

Subagents use `subagent_type: "general-purpose"` with no model argument (inherits).

Cross-model resolvers are stripped on codex/openclaw/hermes/gbrain hosts (`hosts/define-host.ts CROSS_MODEL_RESOLVERS`).
- Sidebar agent routes Sonnet for actions and Opus for analysis (`README.md` "Sidebar agent"; not verified in source here).
- Web research routes Aside agent → host WebSearch → "Search unavailable" (`aside.ts generateAsideResearch`).

## Failure recovery / checkpoints

- `/context-save` writes `checkpoints/<ts>-<title>.md` with bash-sanitized filenames; `/context-restore` prefers current-branch checkpoints then falls back across branches for Conductor handoff (`context-save/SKILL.md.tmpl`, `context-restore/SKILL.md.tmpl`). Continuous checkpoint mode auto-commits WIP with structured bodies.
- `/autoplan` writes a restore point of the plan file before mutating it (Phase 0 Step 1). `/qa` and `/design-review` `git revert HEAD` on regression and stop on risk thresholds. `/investigate` 3-strike rule escalates via AskUserQuestion. Context Health directive asks for `[PROGRESS]` summaries and a stop-and-reassess on loops (`generate-context-health.ts`).
- Runtime: browse daemon exits on Chromium disconnect and the CLI respawns it (`ARCHITECTURE.md` "Crash recovery"); `bin/gstack-detach` runs long evals in their own session with a lock and an `EXIT=` sentinel; Stop hook repairs dangling timeline entries; `gstack-skill-start` never uses `set -e` so a mid-script failure cannot drop STATUS lines; missing `SKILL_START_PROTO: 1` triggers "degraded mode" defaults in prose (`qa/SKILL.md` L42-50).
- Spawned sessions (`SESSION_KIND: spawned`) auto-choose recommended options except destructive ones and end with a completion report (`gstack-skill-start` L519-523).

## Security posture

- Hooks: `careful/bin/check-careful.sh` (PreToolUse on Bash) asks on `rm -rf`, `DROP TABLE`, force-push, `git reset --hard`, `kubectl delete`; hard-denies `rm -r /|~` and force-push to the default branch; detects `${IFS}` and base64-to-shell obfuscation; fails to "ask" when JSON is unparseable. `freeze/bin/check-freeze.sh` (Edit/Write) denies outside `freeze-dir.txt` and fails closed, including on helper load failure (a `trap` backstop). Both share `careful/bin/hook-extract.sh` (python3 or node JSON parsing).
- Prompt-injection: page content envelopes (`browse/src/commands.ts`), L1-L3 filters in `browse/src/content-security.ts`, an int8 BERT classifier in a sidecar (`browse/src/security-classifier.ts`), canary utilities (`browse/src/security.ts`); `GSTACK_INSTRUCTION` blocks are honored only from the direct `gstack-skill-start` tool result with a matching random `SESSION_ID`, and passthrough text is `_sanitize`d (`bin/gstack-skill-start` L57-61, L346-347); tracker text is wrapped by `bin/gstack-issue-guard`; learnings reject instruction-shaped insights; Codex prompts carry a filesystem boundary sentence (`autoplan/SKILL.md.tmpl`, `hosts/codex.ts boundaryInstruction`).
- Secrets: `lib/redact-patterns.ts` (HIGH blocks, MEDIUM confirms, LOW informs) and `bin/gstack-redact` scan the exact bytes before `gh`/`git` sinks; opt-in pre-push hook (`ship/SKILL.md.tmpl` Step 17). Egress: every gstack-initiated network send writes a hash-chained receipt to `~/.gstack/security/egress.jsonl` first; sensitive sinks fail closed, user-facing ones fail open (`lib/egress-receipt.ts`, `bin/gstack-egress-lib.sh`, `test/egress-receipt-wiring.test.ts`).
- Daemon: loopback bind, bearer token 0600, dual-listener tunnel allowlist, cookie decryption in-memory only (`ARCHITECTURE.md` "Security model").
- Residual exposure (read): `scripts/resolvers/browse.ts` embeds `curl -fsSL https://bun.sh/install | bash` (sha256-pinned) inside skill text; `gstack-version-bump --regen-digest` executes repo code during `/ship` (acknowledged in `ship/SKILL.md.tmpl` Step 12); `gstack-update-check` performs a network fetch on nearly every skill start unless `update_check=false`; telemetry is opt-in but the Supabase publishable key is in-repo (`README.md` "Privacy"); Windows v20 cookie exfil path is an open non-goal (`ARCHITECTURE.md` "#1136").

## Host coupling

- Claude Code is the primary host and the only one with sections, hooks, `run_in_background`, plan-mode handling, AskUserQuestion variants, `--disallowedTools` workarounds, and `Co-Authored-By: Claude Opus 4.7` (`hosts/claude.ts`). Other hosts get path rewrites (`~/.claude/skills/gstack` → `$GSTACK_ROOT`), tool-name rewrites (`EXEC_STYLE_TOOL_REWRITES` for OpenClaw/GBrain), frontmatter allowlists, and resolver suppression (`hosts/define-host.ts`, `docs/ADDING_A_HOST.md`).
- Load-bearing Claude Code behaviors pinned in prose/tests: subagents background by default since v2.1.198 (`constants.ts`), hook decision must nest under `hookSpecificOutput` (`careful/SKILL.md.tmpl`), `/checkpoint` renamed because Claude Code shadowed it (`context-save/SKILL.md.tmpl` frontmatter), Conductor disables native AskUserQuestion so prose briefs are the default there (`generate-ask-user-format.ts`), `CLAUDE_PLAN_FILE` for plan mode.
- OS coupling: Aside is macOS-only; Windows needs Node for Playwright pipe transport and file copies instead of symlinks (`README.md` "Windows users"); cookie decryption is macOS Keychain only (`ARCHITECTURE.md`).

## Strengths (ranked, concrete, cited)

1. Verification is evidence-shaped, not vibe-shaped: labelled evidence lines + `GSTACK_STEP_OK` sentinel + screenshots read back into context (`scripts/resolvers/aside.ts`), fix loops that re-run the same script and revert on regression (`qa/SKILL.md.tmpl` 8d-8e), and a content-fingerprinted evidence ledger (`bin/gstack-evidence`, `bin/gstack-wtree`) that makes "tests passed" bind to what is on disk.
2. Docs cannot drift from tools: command and flag tables are generated from `browse/src/commands.ts` and `snapshot.ts`, tier-1 tests parse every `$B` call in SKILL.md against the registry, and `test/context-budget-ratchet.test.ts` fails on token growth (`ARCHITECTURE.md` "SKILL.md template system", `CLAUDE.md` "Token ceiling").
3. The bundled browser is engineered for agents: ref-based snapshots with stale detection, persistent daemon, actionable rewritten errors, untrusted-content envelopes (`browse/src/snapshot.ts`, `commands.ts`, `ARCHITECTURE.md` "Error philosophy").
4. Review fan-out with real merge logic: JSON findings, fingerprint dedup, multi-specialist confidence boost, quote-before-report gate, adaptive gating by historical hit rate (`review-army.ts`, `confidence.ts`, `bin/gstack-specialist-stats`).
5. Runtime-gated preamble: one-time onboarding text only appears when its gate fires and is bound to a session nonce (`bin/gstack-skill-start` L334-347), replacing ~13KB of inline bash per skill (header comment).
6. Injection and egress discipline throughout: learnings/decisions injection filter, tracker-text envelope, fail-closed freeze hook, hash-chained egress receipts with a CI scanner for unreceipted sinks (`lib/jsonl-store.ts`, `bin/gstack-issue-guard`, `freeze/bin/check-freeze.sh`, `test/egress-receipt-wiring.test.ts`).
7. One template, ten hosts, declared as data (`hosts/define-host.ts`).

## Weaknesses (ranked, concrete, cited)

1. Token weight: 12-28K tokens per skill invocation, ~6.5K of it a preamble repeated in every tier-2+ skill, 343K words of rendered skill text, ~21K words of `/ship` sections, and a per-skill 40K ceiling that is a warning only (`test/fixtures/context-budget.json`, `qa/SKILL.md`, `CLAUDE.md` "Token ceiling").
2. Control flow lives in prose the model must obey: bash blocks are separate shells and state is carried by "remember X" (`CLAUDE.md` "Writing SKILL templates"); section reads are pointers with a self-audit at the end ("If you executed any of those steps from memory ... STOP, Read it now", `ship/SKILL.md.tmpl`); manifests deliberately carry no machine predicate.
3. Author-specific and project-specific content leaks into "generic" skills: `plan-eng-review/SKILL.md.tmpl` "My engineering preferences"; `ship/sections/tests.md.tmpl` hardcodes `bin/test-lane`, `npm run test`, and Rails eval globs (`app/services/*_prompt_builder.rb`) despite the repo's own platform-agnostic rule; the Voice directive bans em dashes and a word list; lake-intro pushes a personal blog link (`gstack-skill-start` L397-401).
4. Preamble runtime cost and network on every skill start: ~20 subprocesses (`gstack-config get` x8, `gstack-repo-mode`, `gstack-slug`, `gstack-first-task-detect` "~17-subprocess probe", learnings search, jq over `~/.claude.json`) plus `gstack-update-check` curl (`bin/gstack-skill-start` L70-213).
5. Onboarding chain: lake-intro, telemetry, proactive, routing-injection (commits to the user's CLAUDE.md), two feature-discovery prompts, writing-style migration, pre-push hook offer, plan-tune nudge (`gstack-skill-start` L358-512, `ship/SKILL.md.tmpl` Steps 17 and 21).
6. Primary browser is a proprietary macOS app; on Linux/Windows every browser skill still carries the Aside contract, cookbook and translation table as dead text (`aside.ts`, `browse.ts generateBrowseFallback`).
7. Fragile pins on Claude Code internals (`run_in_background` default flip, hook JSON nesting, Conductor AUQ bug, `/checkpoint` collision) documented as fixed regressions in comments (`constants.ts`, `careful/SKILL.md.tmpl`, `generate-ask-user-format.ts`).
8. Auto-learning does not fire in practice by the repo's own admission (`generate-completion-status.ts` "#2402: 43 of 44 learnings came from explicit /learn").
9. Surface area: 84 bin scripts, sidebar agent with ONNX classifier, ngrok tunnel, iOS QA daemon, gbrain sync, Supabase telemetry, Memorable bridge, design binary; `TODOS.md` lists the ownership gate duplicated in seven places.

## Genuinely innovative vs mostly prompt engineering

- Innovative (code-backed): working-tree fingerprint binding of test evidence and review logs (`bin/gstack-wtree`, `bin/gstack-evidence`, `bin/gstack-review-log`); session-nonce-bound instruction blocks emitted only on gate hit (`gstack-skill-start`); generated skill docs with registry validation and a token ratchet in CI; adaptive specialist gating from persisted hit rates; deterministic never-ask enforcement in a PreToolUse hook (`question-preference-hook.ts`); hash-chained egress receipts with a new-sink CI scanner; ref Locator map with stale-ref fast fail (similar in spirit to Playwright MCP refs, implemented over plain HTTP with no MCP); deny-tier vs ask-tier hook polarity with fail-closed backstops.
- Mostly prompt engineering: personas, "6 Decision Principles", cognitive-pattern lists, WTF-likelihood percentages, ELI10 decision briefs, Boil the Ocean, health score rubrics, the 80-item design audit, cross-model "synthesis" tables, the writing-style and voice directives.

## Unnecessary complexity / scales poorly / wastes tokens / brittle behavior

- Every tier-2+ skill re-ships the full AskUserQuestion format, Conductor/spawned/headless branching and a 13-item self-check (~1.7K words) even for skills that rarely ask (`generate-ask-user-format.ts`).
- `/ship` re-runs the review army and adversarial passes even when `/review` just ran and is CLEAR ("Never skip a verification step", `ship/SKILL.md.tmpl`), doubling subagent and Codex cost.
- Specialists each re-run `git diff` in fresh contexts; a large diff is read N+2 times (`review-army.ts`).
- `codex exec` passes with a 540s timeout inside a 600s Bash timeout; a timed-out pass is declared "MISSING COVERAGE" (`review.ts`), so wall-clock per `/review` can exceed 10 minutes.
- Many `2>/dev/null || true` fail-open paths mean silent degradation is the norm (learnings, review-log, timeline, telemetry); `gstack-update-check` had a "45-release silent-staleness incident" (`bin/gstack-update-check` header).
- Prose branching on echoed STATUS keys (`SESSION_KIND`, `CONDUCTOR_SESSION`, `REPO_MODE`, `CHECKPOINT_MODE`, `EXPLAIN_LEVEL`, `MODEL_OVERLAY`, ...) multiplies conditional text the model must hold in context.
- Windows: file copies instead of symlinks require re-running `./setup` after every pull (`README.md`).
