# Declared-check adoption and batch provenance

The implementation extends `core/checks.py`, `core/jobs.Session`, existing native
hook transports and exact source/external-input qualification. Invocation quoting
uses `core/hosts/setup.py`; no new dependency, shell parser or workflow engine.
The repository declares Apache-2.0. `core/check_batch.py` adds orchestration under
one owner/deadline while sharing the same single-property qualification body.

Both original installed trials and both repaired-runtime requalification trials
remain retained at their original producers. The latter show distinct task
identities, but ordinary compound commands still leave stale/absent evidence.
All six real startup responses emit both property instructions. That observation
does not establish agent consumption or the cause of non-adoption.

The repair exposes readable labels/argument lists and advice on explicit new
verification subjects without inventing coding claims. The added batch feature
offers one executable entry point and retains independent property outcomes.
Filtered advice remains narrow and existing off/continuation rules remain.

The actual Python/Node exercise reuses the independently scoped fixtures from
`eval/input_scopes.py` and synthetic outer-host callbacks from
`eval/declared_checks.py`. It checks pass, external drift, owned failure despite
outer success, recovery and refusal of only the missing input's consumer.
Controlled callbacks and valid references cannot establish installed adoption,
causal coding benefit, exhaustive dependency coverage or OS attestation.

The two subsequent installed Sonnet 5.5 medium conversations both qualify at the
new producer: three tasks each, CURRENT/STALE/FAILED/recovered milestones for the
affected consumer and continuously current independent behavior. Actual owned
calls and callback receipts qualify separately from the literal batch-flag
observations. Both independent arithmetic checks pass and protected inputs stay
unchanged. These successive observations do not estimate the causal effect of
the guidance repair or a coding-quality advantage. See the
[retained outcomes](../../results/check-adoption/installed-acceptance.json).

The subsequent [matched comparison](../../results/matched-workflow/README.md)
completes four conversations and sixteen independently reproduced snapshots.
Both correctness pairs tie, assisted process time is higher, and native owned
adoption is Python 4/4 versus JavaScript 0/4. The controlled prerequisite success
does not generalize to every development workflow or establish a coding benefit.
