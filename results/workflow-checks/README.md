## Measured report work

The [controlled ablation](report-benchmark.json) retains three alternating samples
per mode/language-shaped set, fresh 150-file inputs and five source-wide receipts.
Ordinary output stays VERIFIED with five fresh receipts. Source snapshots fall
from five to two; local medians are Python 0.637→0.284 seconds and JavaScript-shaped
0.633→0.286 seconds. A second run of the public reproducer also completes twelve
valid observations. This measures the report component, not full Stop, model
workflow speed or application performance. Single whole Stop profiles change little.

Fresh opening/closing source/configuration checks, explicit input checks,
coverage gaps and deadlines keep reuse conservative. File-only reports add no
full scan, and separate reports re-read bytes. No cache spans execution or tasks.

The [single-receipt control](single-receipt-benchmark.json) adds work: one legacy
scan becomes two for the closing guard. It and a default five-receipt rerun were
measured during local qualification and partly overlapping component work;
[conditions](report-tradeoff.json) keep their absolute timings separate from the
earlier measurements. The default rerun still gives five-to-two scans. No blanket
report speedup is claimed; use `--receipts 1` with a new output file to reproduce
the tradeoff.
