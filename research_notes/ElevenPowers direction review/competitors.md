# Competitors and complements: products that review or verify AI-agent code (2025-2026)

Research date: 2026-11-22. "Vendor claim" means the figure comes from the vendor's own page or press release with no independent check. GitHub star counts and PyPI release dates were read directly from the GitHub REST API and PyPI JSON API on 2026-11-22 (raw API responses, not a web page; listed as [GitHub API] / [PyPI API] with the repo URL).

## 1. AI code review products: what they check, whether they run tests, test adequacy, pricing, delivery

### Takeaway
Every major AI reviewer (CodeRabbit, Qodo, Graphite/Cursor Bugbot, Copilot, Greptile, Claude Code Review, Sentry Seer, Sourcery, Bito, Gemini) is an LLM reading the diff plus repository context and posting PR comments. Several now run deterministic tools (linters, SAST, CodeQL) in a sandbox, and in November 2026 CodeRabbit began executing the app itself (Verify, end-to-end journeys). None that I found runs the project's own unit tests against the reverted change, or reports mutation survivors or a test-adequacy measure to the reviewer.

### Inferences
- The shared core of the category is an LLM reading the diff and context, with PR comments as the delivery channel. The 2026 differentiators are agentic context gathering, multi-agent verification of candidate bugs, effort levels, learned team rules, and auto-resolve and autofix.
- Execution is moving into review. Copilot runs CodeQL and linters; CodeRabbit runs linters and SAST in a sandbox and now drives the running app (Verify). So "we execute things" alone will not set ElevenPowers apart for long. What still sets it apart is *what* it executes and reports: project tests against the reverted change (pinned or not pinned) and mutants on the diff.
- CodeRabbit Verify's evidence model (results tied to a commit, recordings and logs, environment limits reported separately from failures) is the closest commercial analogue to ElevenPowers' "receipts". Verify is end-to-end UI journeys, though, not unit-test adequacy.
- Pricing has moved to usage-based billing: Bugbot at $1-1.50 per run, Claude Code Review at $15-25 per review, Greptile's overage at $1, Qodo credits. A free, local, open-source tool that uses no model tokens has a clear cost position.

### Gaps

- Amazon Q Developer code review and the status of Amazon CodeGuru Reviewer: no reliable 2025-2026 primary source found in this pass.
- Ellipsis: not researched (no results surfaced).
- Martian Code Review Bench: I did not read the primary page, so its methodology is unverified.
- Copilot's "60 million reviews" figure appears only as a linked post title in the GA changelog. Unverified.

## 2. Test generation and test adequacy tools aimed at AI code (including mutation testing in PRs)

### Takeaway
Mutation-guided test *generation* is established at Meta (ACH in 2025, then Just-in-Time catching tests built for agentic changes in January 2026). Diffblue sells mutation score as a headline metric and gives away a free mutation-based "Test Quality Agent" that runs through AI coding agents. Diff-scoped mutation surfaced in code review has existed for years (Google at scale, from 2021; Arcmutate for pitest posts surviving mutants as PR comments). It remains Java-centric or proprietary, and none of these frame the result as "does the agent's test pin the agent's change".

### Cited Findings

**Meta**
- ACH (Automated Compliance Hardening), Feb 2025 blog and FSE 2025 industry paper. Applied to 10,795 Android Kotlin classes: 9,095 mutants and 571 privacy-hardening tests, with 73% accepted by engineers and 36% judged privacy relevant. 277 of the tests (about 49%) would have been discarded under a line-coverage-only criterion. — [arXiv 2501.12862 (HTML)](https://arxiv.org/html/2501.12862v1); [Meta engineering, 2025-02-05](https://engineering.fb.com/2025/02/05/security/revolutionizing-software-testing-llm-powered-bug-catchers-meta-ach/)
- Follow-up (2025-09-30): LLMs generate problem-specific mutants, plus an LLM equivalent-mutant detector. — [Meta engineering](https://engineering.fb.com/2025/09/30/security/llms-are-the-key-to-mutation-testing-and-better-compliance/)
- Just-in-Time Catching Test Generation (arXiv 2601.22832, 2026-01-30, submitted to FSE 2026 industry track). Generates tests at PR time from the diff, aiming for tests that fail on the change and pass on the parent. 22,126 generated tests; change-aware methods gave 4x more candidate catches than hardening tests and 20x more than coincidentally failing tests. 41 candidate catches reported to engineers, 8 confirmed true positives, 4 of them serious. Rule-based and LLM assessors cut human review load by 70%. The authors name false-positive "development drag" as the main challenge. — [arXiv 2601.22832](https://arxiv.org/abs/2601.22832)
- InfoQ frames JiT as a response to agentic workflows producing large code volumes, with a mutation engine making "dodgy" variants (article 2026-04-17; Meta blog 2026-02-11). — [InfoQ](https://infoq.com/news/2026/04/meta-jit-testing-ai-detection)

**Google (older, pre-2025)**
- "Practical Mutation Testing at Scale" (Petrović, Ivanković, Fraser, Just; arXiv Feb 2021): diff-based mutation surfaced in code review to more than 24,000 developers on more than 1,000 projects, with mutants limited per line and per review and operators chosen by historical usefulness. — [arXiv 2102.11378](https://arxiv.org/abs/2102.11378) (pre-2025, included because it is the model for diff-scoped mutation in review)

**Diffblue**
- Diffblue Testing Agent GA (2026-03-24/25): autonomous regression unit-test generation that delegates to the customer's existing AI coding platform. Vendor benchmark on 8 Java projects: 81% line coverage versus 32% for a senior developer using an AI agent alone, and 61% mutation coverage. — [BusinessWire](https://www.businesswire.com/news/home/20260324227278/en); [Diffblue benchmark report v4 (PDF, vendor)](https://www.diffblue.com/wp-content/uploads/2026/03/Diffblue_AI-Testing-Agents_Benchmark-Report_v4.pdf)
- **Diffblue Test Quality Agent** (free, no licence, Java and Python): runs through a supported AI coding agent (`diffblue-agents run test-quality-report`), detects the build system, installs coverage and mutation tools if missing, and reports line/branch coverage, mutation score and "test strength" (mutants killed among covered mutants) per class or module. — [Diffblue intro](https://www.diffblue.com/resources/introducing-diffblue-test-quality-agent/); [docs](https://docs.diffblue.com/test-quality-quickstart.md) (release date not found)

**Qodo Cover**
- Commercial Qodo Cover (Dec 2024) was built on the open-source Cover-Agent and aims at coverage increase. The open-source repo `qodo-ai/qodo-cover` (AGPL-3.0) has 5,691 stars, last pushed 2026-04-05. The README still describes it as coverage-focused. A third-party guide calls it unmaintained, with last release 0.3.10 on 2025-05-21. — [GitHub API](https://github.com/qodo-ai/qodo-cover); [README](https://raw.githubusercontent.com/qodo-ai/qodo-cover/HEAD/README.md); [qaskills guide](https://qaskills.sh/blog/qodo-cover-ai-test-generation-guide) (secondary); [PR Newswire, Dec 2024](https://prnewswire.com/news-releases/qodo-unveils-fully-autonomous-ai-regression-testing-agent-to-address-growing-code-quality-challenges-302322325.html)

**Mutation-in-PR and open-source mutation tools**
- Arcmutate (commercial pitest extensions): Maven/Gradle plugins post comments and annotations in GitHub PRs and GitLab MRs, showing only surviving mutants. Free licences exist for open source, but the pitest author warns the plugins fit fork-based OSS PRs poorly because of token permissions; a two-workflow workaround is documented. — [pitest blog](https://blog.pitest.org/dont-let-your-code-dry); [pitest blog: fork PRs](https://blog.pitest.org/oss-pitest-pr); [pitest.org](https://pitest.org/)
- StrykerJS incremental mode (since 6.2) re-tests only changed mutants and stores results in a JSON file. It does not detect test changes that affect unchanged mutants, so periodic full runs are recommended. There is no built-in git-diff flag; diff scoping means passing changed files to `--mutate`. — [Stryker docs](https://stryker-mutator.io/docs/stryker-js/incremental/); [Stryker blog](https://stryker-mutator.io/blog/announcing-incremental-mode/)
- Repo activity (GitHub API, 2026-11-22): stryker-js 3,410 stars (pushed 2026-11-21); pitest 1,893 (2026-11-16); mutmut 1,551 (2026-11-19, PyPI 3.8.1 on 2026-10-28); cosmic-ray 667 (PyPI 8.9.0 on 2026-11-10); Mull 863 (2026-11-21); pitest-descartes (extreme mutation) 128 (2026-09-29); mutahunter (LLM mutation, diff-based PR mode) 305 stars, last PyPI release 1.3.2 on 2025-04-17. — [GitHub API: stryker-js](https://github.com/stryker-mutator/stryker-js), [pitest](https://github.com/hcoles/pitest), [mutmut](https://github.com/boxed/mutmut), [cosmic-ray](https://github.com/sixty-north/cosmic-ray), [mull](https://github.com/mull-project/mull), [descartes](https://github.com/STAMP-project/pitest-descartes), [mutahunter](https://github.com/codeintegrity-ai/mutahunter); [PyPI API: mutmut](https://pypi.org/project/mutmut/), [cosmic-ray](https://pypi.org/project/cosmic-ray), [mutahunter](https://pypi.org/project/mutahunter/)
- Thoughtworks Radar lists mutation testing as a technique, suggesting incremental runs on changed code, and describes it as a reinforcement layer against "perpetually green" AI-written tests. — [Thoughtworks Radar](https://www.thoughtworks.com/de-de/radar/techniques/mutation-testing)

**Research on agent-authored tests**
- "All Smoke, No Alarm" (arXiv 2606.18168, 2026-06-16): 80.2% of 86,156 agent-authored test-file patches carry weak or no explicit oracle. Strong-oracle rates on new test files range from 18% (OpenAI Codex) to 67% (Claude Code). After adjustment, strong oracles raise merge odds (OR 1.28). Limitation: the classifier is a regex over diffs, and no mutation scores are reported. — [arXiv 2606.18168](https://arxiv.org/html/2606.18168v1)
- Also relevant (not read in full): SWE-Mutation (ACL 2026 Findings) on whether LLMs can generate reliable test suites; a May 2026 paper on PR-aware unit test generation. — [ACL Anthology](https://aclanthology.org/2026.findings-acl.1976.pdf); [arXiv 2605.25285](https://www.alphaxiv.org/abs/2605.25285)

### Inferences
- Meta's JiT criterion ("fails on the change, passes on the parent") is the generation-side twin of ElevenPowers' pinned check ("some test fails when the change is undone"). Meta *creates* catching tests; ElevenPowers *audits* whether the tests already in the change catch it. This is strong prior art to cite for the borrow-first rule, and a natural complement: ElevenPowers could report "not pinned" and hand off to a generator.
- Diffblue's free Test Quality Agent is the closest product to ElevenPowers' mutation and "test strength" reporting, and it is delivered the same way (through the user's AI coding agent). Differences: it reports per class or module, not per diff or per change; it has no pinned/vacuity check and no receipts; it covers Java and Python only.
- Arcmutate already does "surviving mutants on the diff as PR comments" for the JVM. Diff-scoped mutation reported to reviewers is not new. Doing it language-agnostically, for agent changes, inside the agent loop, is less common.

### Gaps
- Release date of Diffblue Test Quality Agent not found.
- No independent evaluation of Diffblue's benchmark figures found.
- Whether Arcmutate's fork-PR limitation still applies in 2026 not checked.
- Meta's JiT is internal; no external product or open-source release found.

## 3. Agent verification and guardrail plugins; provenance and attestation for agent changes

### Takeaway
The agent-plugin layer is dominated by instruction-style skills (obra/superpowers, about 324k stars), which tell the agent to verify but compute nothing. The closest deterministic competitor I found is `unfaked`, a tiny (1-star) MIT Python tool from August 2026 that runs a revert probe as a Claude Code Stop hook: almost exactly ElevenPowers' pinned/not-pinned check. Provenance tools (Cursor's Agent Trace spec, agentdiff, IETF drafts) record *who* wrote code, not *what evidence* backs it.

### Cited Findings
- obra/superpowers: 323,946 stars, last push 2026-11-03 (GitHub API, 2026-11-22). Its skills include `verification-before-completion` (verify before claiming done) and `test-driven-development` (RED-GREEN-REFACTOR: watch the test fail, then pass). — [GitHub API](https://github.com/obra/superpowers); [skills.sh listing](https://www.skills.sh/obra/superpowers/verification-before-completion)
- **unfaked** (PyPI 0.2.0, 2026-08-26; repo created 2026-08-25; 1 star; MIT; zero dependencies; "no LLM"). It "reverts the changed source files, re-runs only the tests the diff added, and reports every one that still passes", alongside static checks for skipped tests, widened assertions and `except: pass`. Delivered as a Claude Code Stop hook (`uvx unfaked -q --exit-zero`). Self-reported false-alarm control: 240 maintainer commits across flask, requests, pytest, httpx, fastapi and pydantic gave 0 failures and 18 warnings, all real skip/xfail markers. Static checks take 222 ms; the probe has a 20 s budget. — [PyPI API](https://pypi.org/project/unfaked/); [README](https://github.com/cmun2/unfaked); [GitHub API](https://github.com/cmun2/unfaked)
- Other small projects in the same space (dev.to authors): "ClaimCheck" (breaks the fixed code and blocks tests that still pass), "Swarm Orchestrator" (flags relaxed tests, stripped assertions, swallowed errors in PR diffs, advisory by default), and a worktree "swap check" (run head tests on base code). — [dev.to: AI agents cheat on PRs](https://dev.to/moonrunnerkc/ai-agents-cheat-on-pull-requests-i-mined-327-of-them-to-prove-it-43ij/comments); [dev.to: catching shortcuts](https://dev.to/moonrunnerkc/catching-the-shortcuts-ai-coding-agents-take-to-look-done-45mm); [dev.to: tests pass](https://dev.to/moonrunnerkc/your-ais-tests-pass-that-doesnt-mean-the-code-works-239c) (anecdotal, unverified tools)
- Cursor's **Agent Trace**: draft open spec (RFC v0.1.0, January 2026, CC BY 4.0) recording which code ranges came from AI, human, mixed or unknown contributors, linked to conversations. Storage is implementation-defined (files, git notes). It explicitly does not address code quality or bugs. Backed by Cognition, Cloudflare, Vercel, Google Jules, Amp and OpenCode. Thoughtworks Radar placed it at "Assess" (April 2026). — [agent-trace.dev](https://agent-trace.dev/); [InfoQ](https://www.infoq.com/news/2026/02/agent-trace-cursor); [Thoughtworks Radar](https://www.thoughtworks.com/radar/platforms/agent-trace); [Cognition blog](https://cognition.com/blog/agent-trace)
- agentdiff: hooks into Claude Code, Cursor, Codex, Copilot, Windsurf, OpenCode and Gemini, and writes line-level, ed25519-signed, git-native attribution records per commit. — [docs.rs/agentdiff](https://docs.rs/agentdiff)
- IETF individual draft "Identity-Attributed Commits" (Morrison, revisions May-Aug 2026): a commit trailer grammar with Ed25519 signatures over the patch id. Not adopted. — [IETF datatracker](https://datatracker.ietf.org/doc/draft-morrison-identity-attributed-commits/)
- Commentary: `Co-Authored-By` trailers have no cryptographic binding to content; one proposal records receipts in a SCITT log. — [dev.to: Co-authored-by is not enough](https://dev.to/piiiico/co-authored-by-is-not-enough-1nee) (opinion)

### Inferences
- Agent Trace, agentdiff and the trailer drafts attest *authorship*. SLSA, in-toto and GitHub artifact attestations attest *build provenance* (see Gaps). Neither records "these tests were run on tree X and this one fails when the change is reverted". ElevenPowers' receipts could plausibly be emitted as an in-toto-style predicate or attached alongside an Agent Trace record. That would be a complement, not a competitor.
- `unfaked` shows the revert-probe idea is reachable by a solo developer and already packaged as a zero-dependency Claude Code hook. ElevenPowers cannot claim the pinned check alone as unique. Its defensible margin is breadth (diff mutation, function-level extreme mutation, multi-host, receipts, project-independent runner discovery) and the evidence about false-alarm rates.
- superpowers asks for verification while ElevenPowers computes it, so they are complements. The repo's own multistage v3 runs used superpowers in both arms (per project CLAUDE.md).

### Gaps
- I did not check, for this pass, whether SLSA, in-toto or GitHub artifact attestations have agent-specific or test-evidence predicates. Not researched.
- No adoption data for unfaked, agentdiff or Agent Trace beyond stars and backers.
- Claude Code hooks ecosystem (e.g. hook collections that run tests on Stop) not surveyed beyond unfaked.

## 4. Table stakes vs rare; is anyone measuring vacuity or reporting mutation survivors to reviewers?

### Takeaway
Table stakes in 2026 review products: PR-comment delivery on GitHub (often GitLab, Bitbucket, Azure DevOps), an LLM bug-finding pass with whole-repo context, a PR summary, configurable team rules, one-click or autofix suggestions, running linters/SAST, IDE/CLI entry points, and usage or seat pricing with an admin dashboard. Rare: executing the project's tests as review evidence, diff-scoped mutation results for reviewers (Arcmutate for the JVM; Google and Meta internally), and vacuity/pinning checks (Meta JiT internally as a generation criterion; unfaked as a hobby-scale tool). No major commercial reviewer reports "your tests would still pass if this change were reverted".

### Cited Findings
- PR comments plus repo context plus severity ranking across vendors: [Claude Code Review](https://claude.com/blog/code-review); [Copilot GA](https://github.blog/changelog/2026-03-05-copilot-code-review-now-runs-on-an-agentic-architecture/); [Qodo](https://www.qodo.ai/?p=22530); [Greptile v3](https://www.greptile.com/blog/greptile-v3-agentic-code-review)
- Deterministic tools inside review: Copilot (CodeQL, ESLint); CodeRabbit (linters/SAST in sandbox). — [Copilot changelog 2025-12-18](https://github.blog/changelog/2025-12-18-copilot-code-review-preview-features-now-supported-in-github-enterprise-cloud-with-data-residency); [CodeRabbit security post](https://coderabbit.ai/blog/our-security-posture-how-we-safeguard-your-repositories)
- Auto-resolve and autofix: Copilot auto-resolves comments (2026-09-11); Bugbot Autofix. — [Copilot changelog](https://github.blog/changelog/2026-09-11-auto-resolution-and-analysis-updates-in-copilot-code-review); [Cursor blog](https://cursor.com/blog/bugbot-autofix)
- Effort levels: Bugbot (May 2026); Copilot (Oct 2026). — [Cursor](https://cursor.com/blog/may-2026-bugbot-changes); [Copilot changelog](https://github.blog/changelog/2026-10-02-copilot-code-review-api-support-and-new-default-effort-level)
- Test generation offered by reviewers: CodeRabbit (unit-test generation), Sentry (`@sentry generate-test`), Qodo (Cover). — [augmentcode](https://www.augmentcode.com/guides/coderabbit-pricing-costs-limits); [Sentry docs](https://docs.sentry.io/product/ai-in-sentry/ai-code-review); [Qodo Cover repo](https://github.com/qodo-ai/qodo-cover)
- Surviving mutants as PR comments: Arcmutate (JVM). — [pitest blog](https://blog.pitest.org/dont-let-your-code-dry)
- Fail-on-change / pass-on-parent as a test criterion: Meta JiT (internal). — [arXiv 2601.22832](https://arxiv.org/abs/2601.22832)
- Revert probe for agent-added tests: unfaked. — [README](https://github.com/cmun2/unfaked)
- Mutation score and test strength reported through an AI agent: Diffblue Test Quality Agent (per class or module, not per diff). — [Diffblue](https://www.diffblue.com/resources/introducing-diffblue-test-quality-agent/)

### Inferences
- **Table stakes ElevenPowers likely lacks** (from the brief's description of ElevenPowers): a hosted PR-comment/GitHub App delivery path with inline annotations; a PR summary; admin or analytics dashboards; autofix or "hand to agent" buttons; configuration of rules and noise suppression; GitLab/Bitbucket/Azure DevOps reach. Some may be deliberately out of scope for a local plugin, but reviewers live in the PR UI.
- **Differentiated**: computed, non-LLM evidence (pinned/not pinned, diff mutation survivors, untested functions) with receipts tied to a tree, running inside the agent session across five agent hosts, at zero token cost. The only overlaps found are fragments: unfaked (revert probe, Python, Claude Code), Arcmutate (diff mutants, JVM, PR), Diffblue TQA (mutation score, Java/Python, module level), Meta JiT (internal).
- **Watch list**: CodeRabbit Verify shows a major reviewer moving into execution and evidence (commit-tied recordings and logs). If CodeRabbit or Copilot add "run the repo's tests on head and on reverted head" to review, the pinned check becomes table stakes quickly. Mutation is harder for them because of cost and time.

### Gaps
- I found no commercial reviewer stating that it runs the project's existing test suite on head and base. Absence in vendor docs is not proof of absence.
- No survey that quantifies feature prevalence across tools. The table-stakes list is my synthesis of the vendor pages above.

## 5. Adoption numbers, complaints (noise and false positives), evidence of benefit

### Takeaway
Independent evidence on AI reviewers is mixed and points to noise. In the largest field study found, most CodeRabbit comments were rejected (56.3%), mainly as invalid, redundant or out of scope. Vendor metrics (Bugbot's 80% resolution, Claude's under 1% incorrect, Greptile's 82% catch rate) are self-measured and not comparable. For mutation-guided generation, Meta's numbers show real but small yields with false positives as the main cost.

### Cited Findings
- Lin et al., "Is Agentic Code Review Helpful? Mining Developers' Feedback to CodeRabbit Reviews in the Wild" (arXiv 2607.03316, July 2026): 31,073 review/feedback pairs from 10,191 PRs in 239 repos. 36.4% accepted, 7.3% triggered discussion, 56.3% rejected. Rejections were mainly invalid suggestions (false positives, redundant, out of scope); per the search summary, invalid suggestions made up 58.0% of rejections. — [arXiv 2607.03316](https://arxiv.org/abs/2607.03316) (the 58.0% figure comes from a search snippet of [alphaxiv](https://www.alphaxiv.org/abs/2607.03316), not confirmed in the abstract I read)
- Sun et al., "Does AI Code Review Lead to Code Changes? A Case Study of GitHub Actions" (arXiv 2508.18771, Aug 2025): 16 AI review GitHub Actions, more than 22,000 comments in 178 repos. Concise, snippet-bearing, manually triggered, hunk-level comments are more likely to lead to changes. — [arXiv 2508.18771](https://arxiv.org/html/2508.18771v1)
- Vendor benefit metrics: Bugbot 80% of flagged bugs resolved by merge ([Cursor](https://cursor.com/blog/may-2026-bugbot-changes)); Claude Code Review under 1% of findings marked incorrect, substantive-comment PRs up from 16% to 54% ([Claude blog](https://claude.com/blog/code-review)); Greptile 82% on its own 50-bug benchmark ([Greptile](https://greptile.com/benchmarks)); Qodo 60.1% F1 and "+11%" ([GlobeNewswire](https://www.globenewswire.com/news-release/2026/02/04/3232129/0/en/qodo-2-0-redefines-ai-code-review-for-accuracy-and-enterprise-trust.html)).
- Third-party F1 comparison: Greptile 50.2% vs Bugbot 48.3%. — [MorphLLM](https://www.morphllm.com/comparisons/greptile-vs-cursor-review) (third party with a commercial interest)
- Cost complaints: Bugbot usage-pricing threads ([forum](https://forum.cursor.com/t/bugbot-price-hike-135/174859)); Claude Code Review "$25 per pull request" backlash ([levelup.gitconnected, member-only](https://levelup.gitconnected.com/anthropic-wants-25-per-pull-request-devs-are-losing-their-minds-over-claude-code-review-55dbbaca4996); [TechRadar](https://techradar.com/pro/anthropic-launches-a-new-code-review-tool-to-check-ai-generated-content-but-it-might-cost-you-more-than-youd-hope)) (anecdotal)
- Mutation-guided generation yields: ACH 73% acceptance, 49% of tests would be lost under coverage-only ([arXiv 2501.12862](https://arxiv.org/html/2501.12862v1)); JiT 41 candidate catches, 8 true positives, 70% review-load cut from assessors, false positives the main drag ([arXiv 2601.22832](https://arxiv.org/abs/2601.22832)).
- Weak oracles in agent tests: 80.2% of agent test patches weak or no oracle ([arXiv 2606.18168](https://arxiv.org/html/2606.18168v1)). This is evidence that the problem ElevenPowers targets is real and common.
- Adoption signals (GitHub API, 2026-11-22): superpowers 323,946 stars; PR-Agent 16,561; qodo-cover 5,691; stryker-js 3,410; unfaked 1. — [GitHub API links above](https://github.com/obra/superpowers)

### Inferences
- Noise is the category's main complaint, and it is measured, not just anecdotal: the majority of CodeRabbit comments were rejected in the wild. A deterministic, reproducible signal with a published false-alarm control (as unfaked advertises, and as ElevenPowers' rehearsal and held-out work aims to provide) answers that complaint directly, but only if its own noise rate is shown.
- Meta's experience suggests that even execution-based signals produce false positives (flaky or coincidental failures, equivalent mutants), and that filtering is most of the engineering. ElevenPowers' "not pinned" and "survivor" reports will meet the same objection, so publishing rates by state is worth doing.
- Benefit evidence for *test-adequacy reporting to reviewers* (as opposed to bug-finding comments) is close to absent in public sources beyond Google's 2021 deployment and Meta's internal papers.

### Gaps
- No independent study found on whether showing mutation survivors or vacuity to reviewers changes merge outcomes or defect rates for agent-authored PRs.
- No public user counts for CodeRabbit, Bugbot, Greptile or Claude Code Review found in this pass. The "60 million" Copilot review figure is unverified.
- Hacker News and Reddit threads on AI-review noise were not sampled directly in this pass. Complaints above come from vendor forums and press only.
